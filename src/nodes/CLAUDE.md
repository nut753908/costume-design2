# src/nodes/ のガイダンス

全体のアーキテクチャ概要は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## ノードグラフエンジン

React Flow (`src/editor/`) は UI の状態(ノードの位置、選択、ドラッグ)のみを保持します。実際の計算は、React Flow について何も知らない別の純粋関数レイヤーが担当します。

- `nodes/types.ts` — ソケットの型システム(`SocketType`: number/color/enum/geometry/material)と `NodeTypeDefinition`(`inputs`/`outputs` ソケットと `evaluate(inputs, data) -> outputs` 関数を宣言)。`GraphNode`/`GraphEdge` もここで定義されており、React Flow 自身の `Node`/`Edge` 型から切り離された最小限の形になっているため、evaluator は UI ライブラリなしでも利用・テスト可能です。
- `nodes/registry.ts` — `registerNodeType()` / `getNodeType()`。すべてのノードタイプ(入力、ジェネレーター、マテリアル、出力)はここに自身を登録します。`src/nodes/definitions/*.ts` が実際のノードタイプの実装であり、`definitions/index.ts` がそれらすべてを副作用インポートしてレジストリを埋めます。
- `nodes/evaluateGraph.ts` — evaluator 本体。ノードをトポロジカルソートし(Kahn のアルゴリズム、循環がある場合は `GraphCycleError` を投げる)、順番に各ノードの `evaluate()` を評価します。**未接続の入力ソケットは、そのノード自身のリテラルな `data[socketId]` の値にフォールバックします** — これは Geometry Nodes で未接続のソケットがウィジェットのデフォルト値を使うのと同じ挙動であり、単独の(未接続の)ノードでも動作するようにするための中心的な仕組みです。この未接続ソケットの解決ループは `nodes/resolveNodeSockets.ts` の `resolveNodeSockets(type, data)` を経由します(型の静的な `inputs` ではなく、ノードインスタンスの `data.exposedInputs` があればそちらを優先する — グループノードの動的ソケット用、下記「グループノード」節参照)。
- 出力カテゴリのノード(例: `garmentOutput`)には下流のソケットがなく、その `evaluate()` の戻り値は他のノードに消費されるのではなく、Scene から直接読み取られます。

## 新しいノードタイプの追加

手順は `add-node-type` スキルを参照してください。

## グループノード

`nodes/definitions/groupNodeFactory.ts` の `defineGroupNode()` は、複数の既存ノード(`numberMultiply`+generator+`toonMaterial`+`garmentOutput` など)を1つの埋め込みサブグラフとして内包し、外部には限られた入出力ソケットだけを見せる「グループノード」を定義する。`category: 'group'` 固定(`NodeCategory` に追加済み、パレット/コンテキストメニューでは「Groups」セクションに表示される)。`src/state/initialGraph.json` の全15種のガーメント(`<name>GroupNode.ts`、例: `skirtGroupNode.ts`)がこのパターンで定義されている(sleeve も `sleeveGroupNode.ts` として含む — 経緯は下記「値が複数グループで共有される場合」参照)。

- **外部インターフェースは Blender の Geometry Nodes と同じく「Group Input」「Group Output」ノードそのものが定義する**。`nodes/definitions/groupInput.ts`/`groupOutput.ts`(`category: 'group-io'`、パレット/コンテキストメニューでは「Group I/O」セクション — グループの中に入っている間だけ表示される、下記編集UX参照)がこれらのノードタイプで、`data.sockets: GroupIOSocket[]`(`nodes/definitions/groupIOSocket.ts`)という動的なソケット一覧を持つ。`groupInput` は `data.sockets` がそのまま動的な**出力**ソケット一覧に、`groupOutput` は動的な**入力**ソケット一覧になる(`nodes/resolveNodeSockets.ts` がこの2つの型名を特別扱いする)。グループノード本体(`category:'group'`)が外部に見せる入出力ソケットは、埋め込みサブグラフ内にあるこの2ノードの `data.sockets` からそのまま転送される(`resolveNodeSockets()` が `data.nodes` の中から `type: 'groupInput'`/`'groupOutput'` のノードを探して転送する)。**中に入って、この2ノードにソケットを増減・配線するだけで、グループ本体の外部から見えるハンドルが増減する** — 旧実装にあった専用パネル(`editor/GroupIOPanel.tsx`、チェックボックスで内部ノードのソケットを公開/非公開にする方式)は廃止した。`groupInput`/`groupOutput` はどちらも省略可(`defineGroupNode()` は `internalNodes` にこの2ノードが1つも無くてもエラーにしない)で、省略すればそのグループの外部入力/出力ソケットは0個になる — hat/bag/necktie/glasses は他ガーメントと共有される値を1つも持たないため `groupInput` 自体を internalNodes に含めていない。
  - `groupInput` ノードの各ソケットは、未接続時のリテラルなデフォルト値(`socket.default`、enum の選択肢一覧 `socket.options` を含む)を `defineGroupNode()` の登録時テンプレート、または `editor/nodeComponents/GroupInputNode.tsx` の `addSocket()` 内 `defaultForType()`(ソケット追加時に型ごとに割り当てる初期値: number は `0`、color は `'#cccccc'`、enum は `'a'`・`options: ['a', 'b']`)から持つ。**これらは型を問わずノードカード上では一切編集できない**(値そのものを UI から直接いじる手段は無い — 変えたい場合はソケットへ配線して値を供給する)。geometry/material ソケットにはリテラルなデフォルトが無い(未接続なら単に出力されない)。
  - `groupOutput` ノードは、配線された各入力ソケットの値をそのまま素通しする(`editor/nodeComponents/GroupOutputNode.tsx`)。`config.terminalNodeId`(通常は内部の `garmentOutput` 型ノード)が geometry/material/anchor/offsetY のような主要な出力を担うのとは別に、他ガーメントから再引きされたい値を追加公開したい場合に使う仕組み — ただし「あるガーメントの内部値を、別のガーメントだけが特別に覗き見る」という設計は、その値が実は複数ガーメントで**共有**されるべきものだった場合には筋が悪い。現在この用途で使っている実例は無い(下記「値が複数グループで共有される場合」参照)。
  - ソケットの追加は各ノードカード下部の型セレクタ+「+ Add」ボタン、削除は各行の「×」ボタン(`useGraphStore().removeGroupIOSocket(nodeId, socketId)`、下記参照)。ソケットの型は追加時に固定され、後から変更する仕組みは無い(型を変えたい場合は削除して追加し直す — Blender のようにドラッグで繋いだ相手の型を推測してソケットを生成する機能は無い)。
- **内部配線はノードインスタンスごとに独立してキャンバス上で編集できる**。`GroupNodeConfig`(`internalNodes`/`internalEdges`/`terminalNodeId` — `inputs`/`outputs` フィールドは無く、`internalNodes` 内の `groupInput`/`groupOutput` ノードの `data.sockets` から `defineGroupNode()` が登録時に静的な `inputs`/`outputs` を自動導出する)自体は型ごとの固定テンプレートだが、`createDefaultData()` はこのテンプレートを `structuredClone()` した `{nodes, edges}` を返し(`nodes/autoLayout.ts` の `computeAutoLayout()` で座標も自動算出)、ノードインスタンスの `data` に独立したコピーとして持たせる。`evaluate()` は `data.nodes`/`data.edges` があればそちらを優先し、無ければ(`initialGraph.json` の既存インスタンスのように)`config.internalNodes`/`internalEdges` にフォールバックする。パレットから同じ型を複数回追加しても、あるいは既存の `copySelected`/`pasteClipboard`/`duplicateSelected`(いずれも `structuredClone` ベース)で複製しても、各インスタンスは互いに独立している。`terminalNodeId`(内部の`garmentOutput`型ノードのID)はインスタンスごとに変更できない構造的な決定のまま。
  - **編集UX**: `editor/nodeComponents/GenericNode.tsx` でグループノード(`category:'group'`)をダブルクリックすると `useGraphStore().enterGroup(id)` が呼ばれ、キャンバスがそのインスタンスの内部だけの表示に切り替わる(Blender/Houdini方式、React Flow標準の `parentId`/`extent` によるインライン常時表示ではない)。`editor/BreadcrumbPanel.tsx` が現在の階層パスを表示し、クリックで任意の階層(`exitToLevel`)またはトップレベルへ戻れる。中に入っている間の `onNodesChange`/`onConnect`/`addNode`/`updateNodeData`/Undo/Redo/コピペといった編集操作は、`state/graphStore.ts` の既存アクションを一切改修せずにそのまま使っている(`enterGroup`/`exitGroup` がストアの `nodes`/`edges` を丸ごと差し替えるだけなので、既存アクションからは「今どの階層を編集しているか」を区別できない)。多段ネスト(グループの中の別グループ)も自然に成立する。`editor/NodePalette.tsx`/`editor/ContextMenu.tsx` は `scopeStack.length > 0`(=グループの中に入っている)の場合だけ「Group I/O」カテゴリを一覧に含める — トップレベルに置いても意味を持たないため。
  - **落とし穴**: グループの中に入っている間、`state/graphStore.ts` の `nodes`/`edges` は「今開いている階層」の内部ノードだけになるため、これを直接見るコードは他ガーメントの消失やボディスケールのリセットを引き起こしうる(実際に設計時に見つかった欠陥)。トップレベル視点の完全なグラフが必要な箇所は代わりに `rootEvaluatedResults`(`composeRootGraph()` 経由)を見る必要がある — 詳細・対象箇所・回避策は `src/state/CLAUDE.md` の「グループの中に入る」節を参照。
  - **`removeGroupIOSocket(nodeId, socketId)`**(`state/graphStore.ts`): `groupInput`/`groupOutput` ノードのソケットを1つ削除する専用アクション。単なる `updateNodeData()` と違い、(1) 同じハンドルidを参照する現在階層の内部エッジ、(2) グループの中に入っている場合、そのグループノード自身は現在の `nodes` には無く直近の `scopeStack` フレームに退避されているため、そのフレームの `edges`(親ノードから見た外部接続)の中で同じハンドルidに繋がっている外部エッジ、の両方も同時に削除する。外部エッジが残っている場合は削除前に確認ダイアログを出す(孤立エッジ — ハンドルが消えて繋がって見えないエッジ — を防ぐ、上記「グループの中に入る」の落とし穴と同種の対策)。`exitGroup()` 時の書き戻し(`{...n.data, nodes, edges}`)は `nodes`/`edges` だけ上書きするため、内部の `groupInput`/`groupOutput` ノードの `data.sockets` の変更はそのまま親ノードへ引き継がれる。
- `evaluate()` は、外部から渡された入力値(`inputs: Record<string, SocketValue>`)を埋め込みサブグラフ内の `groupInput` ノードの `data.injected` へ評価のたびに一時的に注入してから(`data` として永続化されるわけではない、この1回の `evaluateGraph()` 呼び出し限りのパッチ)、`evaluateGraph()` を**再帰的に**呼ぶだけ。未接続の外部ソケットは `inputs` に現れないため、`groupInput.evaluate()` 側で各ソケット自身の `default` にフォールバックする。`groupInput` ノード自体が無い場合はこの注入先が無いため、`inputs` に何を渡しても単に無視される(そもそも `def.inputs` が空なので外部から接続しようがない)。`nodes/evaluateGraph.ts` 自体はほぼ無改修(未接続ソケットの解決を `resolveNodeSockets()` 経由にした1点のみ変更)。
- **注入できる型に制限は無い**(`groupInput` ノードの出力ソケットとして SocketValue をそのまま流し込むだけなので、geometry/material も注入できる — 旧実装(内部の `numberInput`/`colorInput`/`enumInput` プレースホルダーノードの `data` へリテラル値を上書きする方式)にあった「number/color/enum の3型のみ」という制約は無くなった)。ただし実際に使う既存15種は、他ガーメントと共有される値(`bodyBuild`、pants/shoes/socks 間で共有される `legSpacing`、topGroup/sleeveGroup 間で共有される Torso Radius(スケール済み)/Material)だけを外部入力にしており、ガーメント固有の生パラメータ・Color は外部入力にせず埋め込みサブグラフ内部の `numberInput`/`colorInput`/`enumInput` ノードとして保持している(ルート [`CLAUDE.md`](../../CLAUDE.md) の「ボディスケールはソケットグラフを迂回して直接読み取られる」節参照)。
- **値が複数グループで共有される場合は、その値をどちらかのグループの内部に閉じ込めて `groupOutput` で覗き穴を開けるのではなく、`bodyBuild`/`pantsLegSpacing` と同じく `src/state/initialGraph.ts` 側のトップレベルの共有ノードへ引き上げ、各グループへ普通の外部ソケットとしてファンアウトすること**。topGroup/sleeveGroup がこの例で、Top の生地と同じ色・同じ太さで縫い付けられているように見せる必要がある sleeve のために、Torso Radius の `numberMultiply`(`topRadiusScale`)と Color の `toonMaterial`(`topMaterial`)を**どちらのグループの内部にも置かず**トップレベルの共有ノードとして持ち、両方のグループへ配線している(`topGroupNode.ts`/`sleeveGroupNode.ts` 参照)。以前はこの2つの値を topGroup の内部に置き、`groupOutput` 経由で sleeve だけに再公開していたが、「本来共有すべき値が一方のグループの中に閉じ込められている」という設計上の問題があったため、この形に改めた(`src/geometry/CLAUDE.md` の sleeve の節が元々説明していた「1つの Color/Material ノードから2つの Garment Output へのファンアウト」を文字通り実現している)。
- `garmentOutput.evaluate()` は `outputs: []` 宣言にもかかわらず `anchor`/`offsetY`/`material`/`geometry` を返し、`Garments.tsx` はこれらを宣言済みソケットとは無関係に直接読む。そのため `defineGroupNode()` の `evaluate()` は `config.terminalNodeId`(通常は内部の `garmentOutput` 型ノード)の評価結果を**全キーそのまま**転送する。ここを「`config.outputs` で明示指定したキーだけ返す」ように誤って実装すると、`anchor`/`offsetY` が失われてガーメントの取り付け位置がデフォルトにフォールバックする(実際に踏んだ落とし穴)。
- 新しいガーメント種をこのパターンで追加する手順は `add-garment-type` スキルを参照。
