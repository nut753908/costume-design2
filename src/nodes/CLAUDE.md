# src/nodes/ のガイダンス

全体のアーキテクチャ概要は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## ノードグラフエンジン

React Flow (`src/editor/`) は UI の状態(ノードの位置、選択、ドラッグ)のみを保持します。実際の計算は、React Flow について何も知らない別の純粋関数レイヤーが担当します。

- `nodes/types.ts` — ソケットの型システム(`SocketType`: number/color/enum/geometry/material)と `NodeTypeDefinition`(`inputs`/`outputs` ソケットと `evaluate(inputs, data) -> outputs` 関数を宣言)。`GraphNode`/`GraphEdge` もここで定義されており、React Flow 自身の `Node`/`Edge` 型から切り離された最小限の形になっているため、evaluator は UI ライブラリなしでも利用・テスト可能です。
- `nodes/registry.ts` — `registerNodeType()` / `getNodeType()`。すべてのノードタイプ(入力、ジェネレーター、マテリアル、出力)はここに自身を登録します。`src/nodes/definitions/*.ts` が実際のノードタイプの実装であり、`definitions/index.ts` がそれらすべてを副作用インポートしてレジストリを埋めます。
- `nodes/evaluateGraph.ts` — evaluator 本体。ノードをトポロジカルソートし(Kahn のアルゴリズム、循環がある場合は `GraphCycleError` を投げる)、順番に各ノードの `evaluate()` を評価します。**未接続の入力ソケットは、そのノード自身のリテラルな `data[socketId]` の値にフォールバックします** — これは Geometry Nodes で未接続のソケットがウィジェットのデフォルト値を使うのと同じ挙動であり、単独の(未接続の)ノードでも動作するようにするための中心的な仕組みです。この未接続ソケットの解決ループは `nodes/resolveNodeSockets.ts` の `resolveNodeSockets(type, data)` を経由します(型の静的な `inputs` ではなく、グループノードインスタンス内部の `groupInput`/`groupOutput` ノードの `data.sockets` があればそちらを優先する — グループノードの動的ソケット用、下記「グループノード」節参照)。
- 出力カテゴリのノードのうち `sceneOutput`(`nodes/definitions/sceneOutput.ts`)は、描画専用の終端ノードです。`evaluate()` の戻り値(geometry+material をそのまま素通しするだけ)は、最終的には他のノードに消費されるのではなく `Garments.tsx` が `rootEvaluatedResults` から直接読み取ります。**必ず `<name>Group` の埋め込みサブグラフの中に、`groupOutput` と並べて置く**(既存15種すべてがこの形、下記「グループノード」節参照)— `groupNodeFactory.ts` の `evaluate()` がこの内部 `sceneOutput` の評価結果を `sceneOutputGeometry`/`sceneOutputMaterial` という予約キーへ転送し、グループ自身の外部出力に加える。`Garments.tsx` は `rootEvaluatedResults` の各エントリについて、ノードの型を問わずこの2キーの有無だけを見て描画する。これは「型が geometry+material を持っていれば自動描画される」という暗黙の検出ではなく、「明示的に `sceneOutput` へ配線されているか」が描画対象かどうかの仕様そのものになる(詳細は `src/scene/CLAUDE.md`)。`groupOutput` 自身の `geometry`/`material` ソケット(グループ間で値を再利用したい場合の汎用ソケット、現在は既定では未使用)にどんな値があっても、それだけでは描画対象にはならない — `Garments.tsx` は `groupOutput` 経由の通常出力を一切見ず、`sceneOutput` 経由の予約キーだけを見るため(かつては `sceneOutput` をトップレベルに置く経路もあったが、`sceneOutput` の置き場所を「グループの内部」1箇所に統一し、描画の根拠を単純化した)。

## グループノード

`nodes/definitions/groupNodeFactory.ts` の `defineGroupNode()` は、複数の既存ノード(`numberMultiply`+generator+`toonMaterial`+`enumInput`/`numberInput`+`garmentPlacement` など)を1つの埋め込みサブグラフとして内包し、外部には限られた入出力ソケットだけを見せる「グループノード」を定義する。`category: 'group'` 固定(`NodeCategory` に追加済み、パレット/コンテキストメニューでは「Groups」セクションに表示される)。`src/state/initialGraph.ts` の全15種のガーメント(`<name>GroupNode.ts`、例: `skirtGroupNode.ts`)がこのパターンで定義されている(sleeve も `sleeveGroupNode.ts` として含む — 経緯は下記「値が複数グループで共有される場合」参照)。

- **外部インターフェースは Blender の Geometry Nodes と同じく「Group Input」「Group Output」ノードそのものが定義する**。`nodes/definitions/groupInput.ts`/`groupOutput.ts`(`category: 'group-io'`、パレット/コンテキストメニューでは「Group I/O」セクション — グループの中に入っている間だけ表示される、下記編集UX参照)がこれらのノードタイプで、`data.sockets: GroupIOSocket[]`(`nodes/definitions/groupIOSocket.ts`)という動的なソケット一覧を持つ。`groupInput` は `data.sockets` がそのまま動的な**出力**ソケット一覧に、`groupOutput` は動的な**入力**ソケット一覧になる(`nodes/resolveNodeSockets.ts` がこの2つの型名を特別扱いする)。グループノード本体(`category:'group'`)が外部に見せる入出力ソケットは、埋め込みサブグラフ内にあるこの2ノードの `data.sockets` からそのまま転送される(`resolveNodeSockets()` が `data.nodes` の中から `type: 'groupInput'`/`'groupOutput'` のノードを探して転送する)。**中に入って、この2ノードにソケットを増減・配線するだけで、グループ本体の外部から見えるハンドルが増減する** — 旧実装にあった専用パネル(`editor/GroupIOPanel.tsx`、チェックボックスで内部ノードのソケットを公開/非公開にする方式)は廃止した。`groupInput` は省略可(`defineGroupNode()` は `internalNodes` にこのノードが無くてもエラーにしない)で、省略すればそのグループの外部入力ソケットは0個になる — hat/bag/necktie/glasses は他ガーメントと共有される値を1つも持たないため `groupInput` 自体を internalNodes に含めていない。一方 `groupOutput` は**必須**(下記参照) — グループの出力は必ずこのノードに配線された値になるため、`groupInput` のような省略はできない。
  - `groupInput` ノードの各ソケットは、未接続時のリテラルなデフォルト値(`socket.default`、enum の選択肢一覧 `socket.options` を含む)を `defineGroupNode()` の登録時テンプレート、または `editor/nodeComponents/GroupInputNode.tsx` の `addSocket()` 内 `defaultForType()`(ソケット追加時に型ごとに割り当てる初期値: number は `0`、color は `'#cccccc'`、enum は `'a'`・`options: ['a', 'b']`)から持つ。**これらは型を問わずノードカード上では一切編集できない**(値そのものを UI から直接いじる手段は無い — 変えたい場合はソケットへ配線して値を供給する)。geometry/material ソケットにはリテラルなデフォルトが無い(未接続なら単に出力されない)。
  - `groupOutput` ノードは、配線された各入力ソケットの値をそのまま素通しする(`editor/nodeComponents/GroupOutputNode.tsx`)だけの、`groupInput` と対称なノード。**グループ本体の出力はすべてこのノードに実際に配線された値だけになり、このノードの責務は「配線されたものをまとめて外へ出す」ことだけ**(`defineGroupNode()` は `internalNodes` にこのノードが無いと登録時に例外を投げる)。既存15種のガーメントはどれもここに何もソケットを公開していない(`data.sockets: []`)— geometry/material の描画はこのノードではなく、下記の `sceneOutput` ノードが専用に担っている。他ガーメントから再引きされたい値があれば、`groupOutput` へ配線してここへソケットを追加公開できる — ただし「あるガーメントの内部値を、別のガーメントだけが特別に覗き見る」という設計は、その値が実は複数ガーメントで**共有**されるべきものだった場合には筋が悪い(下記「値が複数グループで共有される場合」参照)。以前は `config.terminalNodeId` という設定値が指す内部ノードの評価結果を、宣言の有無に関わらず丸ごと転送する仕組みだったが、「グループの中で何が実際の出力になっているかが設定を読まないと分からない」という問題があったため廃止し、`groupInput` と同じ「キャンバス上で見える配線そのものが仕様になる」形に統一した(下記の落とし穴も参照)。
  - **配置情報の生成(既存の `enumInput`/`numberInput` を流用)/配置の焼き込み(`garmentPlacement`)の分離**: anchor/offsetY のための専用ノード型は無く、各 `<name>GroupNode.ts` は `anchorIn`(`enumInput`、`data.options` に `['waist', 'shoulder', 'feet', 'wrist', 'head']` を持つ)と `offsetYIn`(`numberInput`)をテンプレート内に置き、その `value` 出力を `garmentPlacement`(`nodes/definitions/garmentPlacement.ts`)へ配線する。`garmentPlacement` は geometry とこの2つの値、そして bodyHeight/bodyBuild/bodyShoulder(下記参照)を受け取り、`geometry/body.ts` の純粋関数で実際のアンカー座標を計算して geometry の頂点そのものを平行移動する — Blender の Geometry Nodes で「別オブジェクトの位置をサンプリングして Translate Geometry に渡す」のと同じ考え方で、取り付け位置をノードグラフの外側を流れるメタデータとして運ぶのではなく geometry の頂点座標に焼き込む。この結果、`sceneOutput`(そして最終的に `Garments.tsx`)は anchor/offsetY を一切知る必要が無く、常に「原点に置けば正しい位置になる」geometry+material の2つだけを扱えばよい。

    かつては `garmentAnchor` という専用ノード(入力を持たず `data.anchor`/`data.offsetY` を出力するだけ)を使っていたが、これは `numberInput`/`enumInput` が既に持つ「固定値+編集可能なドロップダウン/スライダーUI」という形をそのまま重複させただけの型で、しかも入力ソケットを持たないためカード上には読み取り専用の評価値しか表示されず、「どこから来た値か」が伝わらず編集もできないという問題があった。`enumInput`/`numberInput` に置き換えることで、既存の `EnumInputNodeView`/`NumberInputNodeView` がそのまま編集可能なUIを提供し、新しい専用型・専用UIを増やさずに済む(半径・長さ・色などの他のガーメント固有パラメータをグループ内部の `numberInput`/`colorInput`/`enumInput` として保持している既存パターンとも一貫する)。

    さらに、以前は `garmentOutput` という1つのノードが「描画」「配置」に加えて「material 未配線時のフォールバックマテリアル生成」まで担っており責務が混在していたため分割し、「描画専用ノード」として一時的に置いていた `garmentMesh`(geometry+material を素通しするだけのノード)も、`groupOutput`/`sceneOutput` 自身がすでに持つ素通しの挙動と完全に重複する冗長なノードだったため、後に削除して `garmentPlacement`/`toonMaterial` から直接配線する形にした。`<name>GroupNode.ts` の配線は `gen.geometry → placement.geometry`、`anchorIn.value → placement.anchor`、`offsetYIn.value → placement.offsetY`、`input.(bodyHeight/bodyBuild/bodyShoulder) → placement.(同名)`、`placement.geometry → sceneOut.geometry`、`material.material → sceneOut.material` という順になる(`outputIO`(`groupOutput`)自体は `data.sockets: []` で、geometry/material はここへは配線しない — 下記参照)。
  - ソケットの追加は各ノードカード下部の型セレクタ+「+ Add」ボタン、削除は各行の「×」ボタン(`useGraphStore().removeGroupIOSocket(nodeId, socketId)`、下記参照)。ソケットの型は追加時に固定され、後から変更する仕組みは無い(型を変えたい場合は削除して追加し直す — Blender のようにドラッグで繋いだ相手の型を推測してソケットを生成する機能は無い)。
- **内部配線はノードインスタンスごとに独立してキャンバス上で編集できる**。`GroupNodeConfig`(`internalNodes`/`internalEdges` — `inputs`/`outputs` フィールドは無く、`internalNodes` 内の `groupInput`/`groupOutput` ノードの `data.sockets` から `defineGroupNode()` が登録時に静的な `inputs`/`outputs` を自動導出する)自体は型ごとの固定テンプレートだが、`createDefaultData()` はこのテンプレートを `structuredClone()` した `{nodes, edges}` を返し(`nodes/autoLayout.ts` の `computeAutoLayout()` で座標も自動算出)、ノードインスタンスの `data` に独立したコピーとして持たせる。`evaluate()` は `data.nodes`/`data.edges` があればそちらを優先し、無ければ(`initialGraph.ts` の既存インスタンスのように)`config.internalNodes`/`internalEdges` にフォールバックする。パレットから同じ型を複数回追加しても、あるいは既存の `copySelected`/`pasteClipboard`/`duplicateSelected`(いずれも `structuredClone` ベース)で複製しても、各インスタンスは互いに独立している。
  - **編集UX**: `editor/nodeComponents/GenericNode.tsx` でグループノード(`category:'group'`)をダブルクリックすると `useGraphStore().enterGroup(id)` が呼ばれ、キャンバスがそのインスタンスの内部だけの表示に切り替わる(Blender/Houdini方式、React Flow標準の `parentId`/`extent` によるインライン常時表示ではない)。`editor/BreadcrumbPanel.tsx` が現在の階層パスを表示し、クリックで任意の階層(`exitToLevel`)またはトップレベルへ戻れる。中に入っている間の `onNodesChange`/`onConnect`/`addNode`/`updateNodeData`/Undo/Redo/コピペといった編集操作は、`state/graphStore.ts` の既存アクションを一切改修せずにそのまま使っている(`enterGroup`/`exitGroup` がストアの `nodes`/`edges` を丸ごと差し替えるだけなので、既存アクションからは「今どの階層を編集しているか」を区別できない)。多段ネスト(グループの中の別グループ)も自然に成立する。`editor/NodePalette.tsx`/`editor/ContextMenu.tsx` は `scopeStack.length > 0`(=グループの中に入っている)の場合だけ「Group I/O」カテゴリを一覧に含める — トップレベルに置いても意味を持たないため。
  - **落とし穴**: グループの中に入っている間、`state/graphStore.ts` の `nodes`/`edges` は「今開いている階層」の内部ノードだけになるため、これを直接見るコードは他ガーメントの消失やボディスケールのリセットを引き起こしうる(実際に設計時に見つかった欠陥)。トップレベル視点の完全なグラフが必要な箇所は代わりに `rootEvaluatedResults`(`composeRootGraph()` 経由)を見る必要がある — 詳細・対象箇所・回避策は `src/state/CLAUDE.md` の「グループの中に入る」節を参照。
  - **`removeGroupIOSocket(nodeId, socketId)`**(`state/graphStore.ts`): `groupInput`/`groupOutput` ノードのソケットを1つ削除する専用アクション。単なる `updateNodeData()` と違い、(1) 同じハンドルidを参照する現在階層の内部エッジ、(2) グループの中に入っている場合、そのグループノード自身は現在の `nodes` には無く直近の `scopeStack` フレームに退避されているため、そのフレームの `edges`(親ノードから見た外部接続)の中で同じハンドルidに繋がっている外部エッジ、の両方も同時に削除する。外部エッジが残っている場合は削除前に確認ダイアログを出す(孤立エッジ — ハンドルが消えて繋がって見えないエッジ — を防ぐ、上記「グループの中に入る」の落とし穴と同種の対策)。`exitGroup()` 時の書き戻し(`{...n.data, nodes, edges}`)は `nodes`/`edges` だけ上書きするため、内部の `groupInput`/`groupOutput` ノードの `data.sockets` の変更はそのまま親ノードへ引き継がれる。
- `evaluate()` は、外部から渡された入力値(`inputs: Record<string, SocketValue>`)を埋め込みサブグラフ内の `groupInput` ノードの `data.injected` へ評価のたびに一時的に注入してから(`data` として永続化されるわけではない、この1回の `evaluateGraph()` 呼び出し限りのパッチ)、`evaluateGraph()` を**再帰的に**呼ぶだけ。未接続の外部ソケットは `inputs` に現れないため、`groupInput.evaluate()` 側で各ソケット自身の `default` にフォールバックする。`groupInput` ノード自体が無い場合はこの注入先が無いため、`inputs` に何を渡しても単に無視される(そもそも `def.inputs` が空なので外部から接続しようがない)。`nodes/evaluateGraph.ts` 自体はほぼ無改修(未接続ソケットの解決を `resolveNodeSockets()` 経由にした1点のみ変更)。
- **注入できる型に制限は無い**(`groupInput` ノードの出力ソケットとして SocketValue をそのまま流し込むだけなので、geometry/material も注入できる — 旧実装(内部の `numberInput`/`colorInput`/`enumInput` プレースホルダーノードの `data` へリテラル値を上書きする方式)にあった「number/color/enum の3型のみ」という制約は無くなった)。ただし実際に使う既存15種は、他ガーメントと共有される値(`bodyBuild`、pants/shoes/socks 間で共有される `legSpacing`、topGroup/sleeveGroup 間で共有される Torso Radius(スケール済み)/Material)だけを外部入力にしており、ガーメント固有の生パラメータ・Color は外部入力にせず埋め込みサブグラフ内部の `numberInput`/`colorInput`/`enumInput` ノードとして保持している(ルート [`CLAUDE.md`](../../CLAUDE.md) の「ボディスケールはソケットグラフを迂回して直接読み取られる」節参照)。**`bodyHeight`/`bodyBuild`/`bodyShoulder` の3つだけは例外的に全15グループへ無条件で配線されている** — `garmentPlacement`(下記参照)がアンカー座標を計算するために必要だからで、そのガーメント自身の半径スケーリングに `bodyBuild` を使わないガーメント(hat/bag/necktie/glasses/top/sleeve)であっても、この3つは外部ソケットとして持つ。
- **値が複数グループで共有される場合は、その値をどちらかのグループの内部に閉じ込めて `groupOutput` で覗き穴を開けるのではなく、`bodyBuild`/`pantsLegSpacing` と同じく `src/state/initialGraph.ts` 側のトップレベルの共有ノードへ引き上げ、各グループへ普通の外部ソケットとしてファンアウトすること**。topGroup/sleeveGroup がこの例で、Top の生地と同じ色・同じ太さで縫い付けられているように見せる必要がある sleeve のために、Torso Radius の `numberMultiply`(`topRadiusScale`)と Color の `toonMaterial`(`topMaterial`)を**どちらのグループの内部にも置かず**トップレベルの共有ノードとして持ち、両方のグループへ配線している(`topGroupNode.ts`/`sleeveGroupNode.ts` 参照)。以前はこの2つの値を topGroup の内部に置き、`groupOutput` 経由で sleeve だけに再公開していたが、「本来共有すべき値が一方のグループの中に閉じ込められている」という設計上の問題があったため、この形に改めた(`src/geometry/CLAUDE.md` の sleeve の節が元々説明していた「1つの Color/Material ノードから2つの Garment Output へのファンアウト」を文字通り実現している)。
- **`sceneOutput` はグループの埋め込みサブグラフの中に、`groupOutput` と並べて置く**(既存15種すべてがこの形。かつては `groupOutput` の `geometry`/`material` ソケットへ `garmentPlacement`/`toonMaterial` の出力を直接配線し、グループの外側にトップレベルの `<name>Output` ノードを置いてそこから読む形だったが、`sceneOutput` をグループの内部に置くだけで完結する現在の形に一本化し、`groupOutput` は空(`data.sockets: []`)にした)。中に入って `sceneOutput` ノードを `garmentPlacement`/`toonMaterial` などから配線すると、`groupNodeFactory.ts` の `evaluate()` が(1) `internalNodes` の中から `type === 'sceneOutput'` のノードを探し(`groupOutput` を探すのと同じ、型名によるパターン)、(2) その評価結果が geometry+material の両方を持っていれば、`sceneOutputGeometry`/`sceneOutputMaterial` という予約キーでグループ自身の外部出力(`groupOutput` 転送分と同じ Record)へ追加する。この2キーはグループの静的な `outputs`(`groupOutput.data.sockets` から導出される、パレット上で見える入出力ソケット)には含まれず、他ノードへ配線するための一般的なソケットではない — `Garments.tsx` だけが読む専用チャンネルで、`numberDisplay` が `outputs: []` としながら `evaluate()` で `value` キーを返すのと同じパターン。`Garments.tsx` はグループの型を問わずこの2キーの有無だけを見る(上記「出力カテゴリのノード」節、`src/scene/CLAUDE.md` 参照)。この内部配線を消してしまう(または `sceneOutput` ノード自体・その入力を削除してしまう)と、そのガーメントは単に描画されなくなる(フォールバックを持つ中継ノードは無い)。`anchor`/`offsetY` はこの経路には一切乗らない — `garmentPlacement` が内部で消費してジオメトリの頂点座標へ焼き込むため、`anchorIn`/`offsetYIn → garmentPlacement` の配線を消すと(`garmentPlacement` 自身もフォールバック `anchor: 'waist'`/`offsetY: 0` を持つので)取り付け位置だけがデフォルトに戻り、描画自体は消えない。多段ネスト(グループの中の別グループ)の場合、この転送は1階層だけで、ネストした孫グループの内部 `sceneOutput` を祖父グループが自動的にさらに転送する、ということはしない(既存15種に多段ネストの実例が無いため、必要になった時点で検討する)。
- 新しいガーメント種をこのパターンで追加する手順は `add-garment-type` スキルを参照。
