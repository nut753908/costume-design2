# src/geometry/ のガイダンス

全体のアーキテクチャ概要(手続き的生成・外部アセット不使用という制約を含む)は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## カスタムガーメントジオメトリ

ガーメントは全14種類(skirt/top(袖込み)/pants/shoes/gloves/hat/belt/scarf/jacket/socks/dress/bag/necktie/glasses)あり、いずれも専用の `build*Geometry()` を持たず、既存の汎用ノードの組み合わせだけで完全にノードグラフ上に表現されている — top は `easedLatheCurve`/`ringGridGenerator`/`sleevePair`(袖)/`mergeGeometry`、dress は `easedLatheCurve`/`ringGridGenerator`(`nodes/definitions/groups/topGroupNode.ts`/`dressGroupNode.ts` 参照、下記参照)、belt は `bulgedBand`(`nodes/definitions/groups/beltGroupNode.ts` 参照、下記 belt の項も参照)、scarf は `bulgedBand`/`boxGenerator`/`translate`/`mergeGeometry`(`nodes/definitions/groups/scarfGroupNode.ts` 参照)、necktie は `boxGenerator`/`translate`/`taperedRectTubeGenerator`/`mergeGeometry`(`nodes/definitions/groups/necktieGroupNode.ts` 参照)、shoes は `easedLatheCurve`/`latheGenerator`/`scale`/`mirrorPair`(`nodes/definitions/groups/shoesGroupNode.ts` 参照、下記参照)、bag/glasses は `boxGenerator`/`torusGenerator`/`alignedBoxGenerator`/`translate`/`mirrorPair`/`mergeGeometry`(`nodes/definitions/groups/bagGroupNode.ts`/`glassesGroupNode.ts` 参照、下記参照)。共有ヘルパー:

- `latheProfile.ts` — `EasedLatheCurve`(`THREE.Curve<Vector2>`)。アンカー側から反対側の端まで、半径を smoothstep でイージングしながら結ぶ `(半径, 高さ)` のプロファイルの曲線で、点列は受け取る側が `getPoints(steps)` で取り出す。大半のガーメント(skirt/pants/shoes/gloves/hat/belt/jacket/socks など)はこれを `THREE.LatheGeometry` に渡すだけの単純な回転体。skirt/pants(脚)/shoes/gloves/hat/jacket/socks の7種は、この関数呼び出し自体もノードグラフ側の汎用ノード `easedLatheCurve`(`nodes/definitions/generic/easedLatheCurve.ts`)+`latheGenerator`(`nodes/definitions/generic/latheGenerator.ts`、生の `THREE.LatheGeometry` ラッパー)へ切り出されており、対応する `<name>GroupNode.ts` から直接呼ばれる(下記参照)。この2ノードの間を流れる値(`(半径, 高さ)` の曲線)には `nodes/types.ts` の `SocketType`/`SocketValue` に `'curve'` という専用の型がある(`nodes/CLAUDE.md` 参照)。プロファイルの分割数 `Profile Steps`(既定10、skirt のみ12)は `latheGenerator`/`ringGridGenerator` 側のカード上の入力欄で、向きは `easedLatheCurve` の出力ソケット `Curve Up`/`Curve Down` のどちらを配線するかで選ぶ(数値の `direction` は持たない)。skirt/jacket/dress の裾半径(`hemRadius = radius * (1 + Math.max(0, flare))`)は `numberMax`(`numberAdd`/`numberSubtract`/`numberMultiply` と対になる二項演算ノード、`nodes/definitions/generic/numberMax.ts`)→`numberAdd`→`numberMultiply` という可視の配線へ展開してから `profile.endRadius` へ渡している(`flaredRadius` の定数 0/1 は `numberMax`/`numberAdd` の `B` 入力欄の値)。belt(プロファイルを2回呼んで連結する)は `easedLatheCurve`(`lowerProfile`/`upperProfile`)+`translateCurveY`(曲線を Y方向にだけ平行移動する)/`concatCurve`(2つの曲線を前半・後半につなぐ)へ展開し、`bulgedBand`(`nodes/definitions/generic/bulgedBand.ts`)へまとめられ、belt と scarf が共有する。shoes はつま先方向に伸びた楕円形のシルエットを作る非一様スケール(`.scale(1, 1, toeLength)`)も `scale`(X/Y/Z を持つ汎用の非一様スケールノード、`translate` と対になる形、`nodes/definitions/generic/scale.ts`)の Z 入力欄だけを使って展開している。 同じファイルの `EllipticLatheCurve` は、アンカー側で水平・反対端で垂直になる楕円の 1/4 の曲線で、`shoulderedProfile` が服の肩の丸み(首まわりを水平に閉じる)に使う(smoothstep だと首まわりが短い垂直の筒になり、襟の両脇が尖る)。
- 左右対称なパーツ(Body の腕/脚1組、pants の左右2脚、shoes の左右2本、gloves の左右2つ、socks の左右2本)の「±offset だけ平行移動して結合する」処理は、`geometry/` 側の専用関数としては存在しない。ノードグラフ上の `translate`(`translate.ts`、X だけを配線)+`mirrorX`(`mirrorX.ts`、+側を X=0 について鏡像反転して -側にする)+`mergeGeometry`(`mergeGeometry.ts`、`mergeGeometries()`+`computeVertexNormals()` を切り出した汎用ノード)を内包するグループノード `mirrorPair`(`nodes/definitions/generic/mirrorPair.ts`)へ全ガーメント分統一されている。各ガーメントの `geometry/*.ts` はこの切り出しにより「1つぶんの形状を作る関数(`buildPantsLegGeometry()`/`buildGloveGeometry()`/`buildSockGeometry()`)」だけを持ち、左右対称ペア化のロジックは持たない(shoes は `geometry/shoes.ts` 自体が無く、プロファイル生成+Lathe化+非一様スケールもすべてノードグラフ側にある、上記参照)。
- `splineProfile.ts` — `SplineProfileCurve`。等間隔の高さに置いた制御半径を、半径の2乗に対する曲率連続の3次スプライン(両端は2次式で打ち切る)でつなぐ `(半径, 高さ)` のプロファイル曲線。半径 0 の端は球の極のように丸く閉じる(半径そのものを補間すると円錐のようにとがる)。単調性を保つ補間(PCHIP)は極値の点で傾きが 0 になり曲率も不連続なので、少ない制御点だと輪郭が箱のように角ばる。`profileCurve` ノードが使い、`torsoShape`(胴体の幅・前後の輪郭)が `loftGenerator` と組み合わせて使う。
- `splineProfile.ts` の `SignedSplineCurve` は、符号付きの制御値(輪の前後のずらし量など)を値そのものに対する3次スプラインでつなぐ `(値, 高さ)` の曲線。`signedProfileCurve` ノードが使う。
- `voxelRemesh.ts` — `voxelRemesh()`。箱の中だけを Z 方向の光線の巻き数でボクセル化(重なった閉じたメッシュの和集合になる)→ガウスぼかし→マーチングキューブ(three.js の `edgeTable`/`triTable`、「値がしきい値より小さい角」基準の向きで、占有率が高い側が外向きになる)で作り直し、箱の外は元の面のまま `overlap` だけ重ねて残す。元の頂点は先頭にそのまま並ぶ。作り直した頂点の法線は、面法線の平均ではなくぼかした占有率の勾配から求める(トゥーンの陰影の境界が波打たない)。作り直した面は境目で元の面と重なるため、深度が競合しないよう内側へ 0.1 ボクセルだけ沈める。ぼかしで生じる数 mm のずれが境目の段差・ひげにならないよう、箱の縁に近い作り直した頂点は元の面上の最近点へ寄せる(縁で完全に、`overlap` の2倍先で 0 になるよう滑らかに弱める)。ぼかしで細い部分(σ=2 ボクセルで脚・腕)は痩せるので、全身ではなく継ぎ目を消したい範囲に限る。`nodes/definitions/generic/voxelRemesh.ts` がノードに配線する。
- `neckline.ts` — `necklineWeight(weights, angle)`。ノードグラフ側で作られた落ち込み量の曲線(正面からの角度を 0〜1 に正規化した値を x、重みを y とする曲線(`THREE.Curve<Vector2>`、`functionCurve.ts` の `FunctionCurve`)。round/v/square の形は `generic/necklineShapes.ts` の `necklineShapes` グループが作る)を、角度の位置で評価して返す、`ringGrid.ts` が使うフォールオフ関数。正面から±90° を超えると常に0。
- `ringGrid.ts` — `buildRingGridGeometry()`。角度×高さのリングからなる手組みの `BufferGeometry` を、行ごとの半径/Y座標のリストから組み立て、角度ごとに「最上段から `necklineDepth` × 重み(`necklineWeights`(落ち込み量の曲線)を `neckline.ts` のフォールオフ関数で角度ごとに引いたもの)だけ下がった線」より上にある行の頂点を、その線上の点(半径は上下の行から補間)へ寄せてネックラインを彫り込む。最上段だけを下げる方式だと、肩の丸みで行の間隔が狭い所では下の行を越えて面が折り返す。`nodes/definitions/generic/ringGridGenerator.ts` がノードグラフへ薄く配線し、top/dress が共有する。
- `taperedTube.ts` — `buildTaperedTube()`。始点から終点まで、両端の断面(幅×厚み、楕円または矩形)を直線的に補間する、キャップ無しの2リングのチューブ。軸が Y と平行でなければ断面の幅方向(tangent)は水平、そうでなければ +X(`tubeFrame()`)。`nodes/definitions/generic/taperedTubeGenerator.ts`(断面の形ごとに `taperedEllipseTubeGenerator`/`taperedRectTubeGenerator` の2ノードを登録する)がノードグラフへ薄く配線する(`curve` 型を扱う `latheGenerator.ts` と同じ理由で `defineGeneratorNode()` ではなく直接 `registerNodeType()` で定義)。頂点属性は position/normal のみ(uv 無し、`mergeGeometry` が uv の有無の違いを吸収する)。
- `alignedBox.ts` — `buildAlignedBox()`。2点間を結ぶよう回転+平行移動した `THREE.BoxGeometry` を作る。回転+平行移動のみの剛体変換なので、標準プリミティブが元々持つ正しい巻き順がそのまま保たれる。`nodes/definitions/generic/alignedBoxGenerator.ts` がノードグラフへ薄く配線する(始点・終点をそれぞれ X/Y/Z の3ソケットに分解しているのは、座標を求める四則演算チェーンを可視の配線として展開できるようにするため。`curve` 型を扱う `latheGenerator.ts` と同じ理由で `defineGeneratorNode()` ではなく直接 `registerNodeType()` で定義している)。bag のストラップ・glasses のブリッジ/テンプルが使う。

放射対称な Lathe では表現できない形状は、それぞれ別の技術で構築しています:

- top/dress は専用の `build*Geometry()` を持たない。Lathe/Extrude では**ない**(ネックラインの落ち込みは放射対称ではないため)。どちらも `shoulderedProfile`(`nodes/definitions/generic/shoulderedProfile.ts`、首まわりの開口から体のなで肩に沿う丸みで胸まで広がり、そこから裾へ伸びるプロファイル。jacket も `latheGenerator` と組み合わせて使う)→`ringGridGenerator`(`ringGrid.ts` の `buildRingGridGeometry()` を呼ぶ、`latheGenerator` の放射非対称版)という同じ2ノードで組む。top は胸から裾まで一定半径、dress は胸から裾(hemRadius、`flaredRadius` で胸の半径から導出)へイージングし、`latheGenerator` と同じ、曲線を `Profile Steps` 分割した下→上の順の点列を `ringGridGenerator` が上→下へ並べ直して渡す。
- 袖は専用の `build*Geometry()` を持たず、汎用グループ `sleevePair`(`nodes/definitions/generic/sleevePair.ts`)が原点から水平より88°下(ほぼ真下)へ `sleeveLength` だけ伸びる `taperedEllipseTubeGenerator` 1本(円形断面、終端の直径は始端の0.85倍)と、付け根の開口をふさぐ `sleeveRadius` の球を作り、`mirrorPair` で腕の中心と同じ `±shoulderSpacing` へ複製して左右の袖にする(左袖は `mirrorPair` 内の鏡像反転)。Top 本体の壁面とは重ねたままにしている(意図的な交差を許容するアプローチで、ブーリアン演算や穴あけは行わない)。`topGroup` の内部で `ringGridGenerator` と並べて使われ、`bodyDimensions.shoulderSpacing` を外部ソケットで受け取って袖の横位置に使い、結合後の1つのジオメトリとして同じ `toonMaterial`・同じ `shoulder` アンカーで描画される。これにより top の色を変えると袖も一緒に再着色される(`nodes/definitions/groups/topGroupNode.ts` 参照)。
- マネキンの寸法計算(`heightScale`/`buildScale`/`shoulderScale` から各部位の半径・長さ・Y座標、および `waist`/`shoulder`/`feet`/`wrist`/`head` アンカー座標を求める式)は、`geometry/` 配下の純粋関数としては存在しません。式の実体は `bodyDimensionsGroupNode.ts`/`bodyLayoutGroupNode.ts` というノードグラフのテンプレート定義そのものが唯一の真実の源です(コード側に並行する純粋関数は無い、ノードエディタ上で式がそのまま見える形にするため)。`bodyDimensionsGroup`/`bodyLayoutGroup` 自体は `bodyGroupNode.ts`/`garmentPlacement.ts` のどちらにもネストされておらず、`src/state/initialGraph.ts` 側のトップレベル共有ノード(id: `bodyDimensions`/`bodyLayout`)としてただ1組だけ存在し、`bodyGroup` と全14ガーメントへ計算済みの値をファンアウトする(`nodes/CLAUDE.md` の「グループノード」節参照)。ボディのリサイズに合わせてアンカーが一緒に動きます。

**すでに一度踏んだ落とし穴(新しいジオメトリを追加すると再びハマります):**

- 三角形の巻き順(winding order)は重要で、逆になりやすいです。逆になると手前側の面が `FrontSide` のカリングで消え、奥側の面の内側だけが見える(形が欠けて見える/陰影がおかしい)状態になります。新しい手続き型メッシュがそう見えたら、まずマテリアルやライティングではなく三角形の巻き順を確認してください。`windingTestHelpers.ts` の `expectOutwardWinding()` で自動検証できますが、対象が単純な放射対称形状でない場合は既定の axisPoint(Y軸基準)では誤検知します — 箱(BoxGeometry)には自身の中心点、トーラス(TorusGeometry)には中心線円上の最近点というように、形状に応じた正しい基準点を渡す必要があります(`alignedBox.test.ts` 参照)。
- `mergeGeometries()`(`three/examples/jsm/utils/BufferGeometryUtils.js`)は、結合するすべてのジオメトリが**同じ頂点属性**(名前・itemSize)を持っていることを要求します。標準プリミティブ(position/normal/uv を持つ)と手組みの `BufferGeometry`(position のみ)を混ぜて結合しようとすると、警告を出して `null` を返し、その後の呼び出しが `Cannot read properties of null` で落ちます(`mergeGeometry` ノードは uv の有無だけが違う場合、入力を clone して uv を外してから結合し直すため、`boxGenerator` と `taperedRectTubeGenerator` のような組み合わせを普通に繋げる)。
- アンカーは体の中心線(x=0, z=0)上の1点のみです。体の前面より前に出すべきアクセサリ(ネクタイ、バッグ、メガネなど)は、z=0 付近に置くとガーメントの壁の内側/裏側に埋もれて見えなくなります(`necktieGroupNode.ts` の `scale`(胴体半径 × 1.15)、`bagGroupNode.ts` の `bagFrontDepthCalc`(胴体半径 × 0.69)/`glassesGroupNode.ts` の `forwardDepthCalc`(頭半径 − 定数)を参照)。さらに、デフォルトグラフのように複数のガーメントが同じアンカーを同時に共有していると、後から広がる大きなガーメント(dress/jacket など)が薄いアクセサリ(necktie/bag など)を覆い隠すことがあります — これはバグではなく、複数の出力ノードが同じアンカーを共有する際の一般的な特性です(`src/scene/CLAUDE.md` の「シーン組み立て」参照)。
