# src/geometry/ のガイダンス

全体のアーキテクチャ概要(手続き的生成・外部アセット不使用という制約を含む)は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## カスタムガーメントジオメトリ

ガーメントは全14種類(skirt/top(袖込み)/pants/shoes/gloves/hat/belt/scarf/jacket/socks/dress/bag/necktie/glasses)あり、いずれも専用の `build*Geometry()` を持たず、既存の汎用ノードの組み合わせだけで完全にノードグラフ上に表現されている — top は `easedLatheProfile`/`ringGridGenerator`/`sleevePair`(袖)/`mergeGeometry`、dress は `easedLatheProfile`/`ringGridGenerator`(`nodes/definitions/groups/topGroupNode.ts`/`dressGroupNode.ts` 参照、下記参照)、belt は `bulgedBand`(`nodes/definitions/groups/beltGroupNode.ts` 参照、下記 belt の項も参照)、scarf は `bulgedBand`/`boxGenerator`/`translate`/`mergeGeometry`(`nodes/definitions/groups/scarfGroupNode.ts` 参照)、necktie は `boxGenerator`/`translate`/`taperedRectTubeGenerator`/`mergeGeometry`(`nodes/definitions/groups/necktieGroupNode.ts` 参照)、shoes は `easedLatheProfile`/`latheGenerator`/`scaleZ`/`mirrorPair`(`nodes/definitions/groups/shoesGroupNode.ts` 参照、下記参照)、bag/glasses は `boxGenerator`/`torusGenerator`/`alignedBoxGenerator`/`translate`/`mirrorPair`/`mergeGeometry`(`nodes/definitions/groups/bagGroupNode.ts`/`glassesGroupNode.ts` 参照、下記参照)。共有ヘルパー:

- `latheProfile.ts` — `buildEasedLatheProfile()`。アンカー側から反対側の端まで、半径を smoothstep でイージングしながら結ぶプロファイル点列を生成する。大半のガーメント(skirt/pants/shoes/gloves/hat/belt/jacket/socks など)はこれを `THREE.LatheGeometry` に渡すだけの単純な回転体。skirt/pants(脚)/shoes/gloves/hat/jacket/socks の7種は、この関数呼び出し自体もノードグラフ側の汎用ノード `easedLatheProfile`(`nodes/definitions/generic/easedLatheProfile.ts`)+`latheGenerator`(`nodes/definitions/generic/latheGenerator.ts`、生の `THREE.LatheGeometry` ラッパー)へ切り出されており、対応する `<name>GroupNode.ts` から直接呼ばれる(下記参照)。この2ノードの間を流れる値(`THREE.Vector2[]` の点列)には `nodes/types.ts` の `SocketType`/`SocketValue` に `'points'` という専用の型がある(`nodes/CLAUDE.md` 参照)。`easedLatheProfile` の `steps`(プロファイルの分割数、既定10、skirt のみ12)はカード上の入力欄で、向きは出力ソケット `Points Up`/`Points Down` のどちらを配線するかで選ぶ(数値の `direction` は持たない)。skirt/jacket の裾半径(`hemRadius = radius * (1 + Math.max(0, flare))`)は `numberMax`(`numberAdd`/`numberSubtract`/`numberMultiply` と対になる二項演算ノード、`nodes/definitions/generic/numberMax.ts`)→`numberAdd`→`numberMultiply` という可視の配線へ展開してから `profile.endRadius` へ渡している(`flaredRadius` の定数 0/1 は `numberMax`/`numberAdd` の `B` 入力欄の値)。belt(プロファイルを2回呼んで連結する)は `easedLatheProfile`(`lowerProfile`/`upperProfile`)+`translatePointsY`(points を Y方向にだけ平行移動する、`translate` の points 版)/`slicePoints`(points の末尾から指定個数を取り除く)/`concatPoints`(2つの points を連結する、`mergeGeometry` の points 版)へ展開し、`bulgedBand`(`nodes/definitions/generic/bulgedBand.ts`)へまとめられ、belt と scarf が共有する。shoes はつま先方向に伸びた楕円形のシルエットを作る非一様スケール(`.scale(1, 1, toeLength)`)も `scaleZ`(1軸だけを扱う汎用の非一様スケールノード、`nodes/definitions/generic/scaleZ.ts`)へ展開している。
- 左右対称なパーツ(Body の腕/脚1組、pants の左右2脚、shoes の左右2本、gloves の左右2つ、socks の左右2本)の「±offset だけ平行移動して結合する」処理は、`geometry/` 側の専用関数としては存在しない。ノードグラフ上の `translate`(`translate.ts`、X だけを配線)+`mirrorX`(`mirrorX.ts`、+側を X=0 について鏡像反転して -側にする)+`mergeGeometry`(`mergeGeometry.ts`、`mergeGeometries()`+`computeVertexNormals()` を切り出した汎用ノード)を内包するグループノード `mirrorPair`(`nodes/definitions/generic/mirrorPair.ts`)へ全ガーメント分統一されている。各ガーメントの `geometry/*.ts` はこの切り出しにより「1つぶんの形状を作る関数(`buildPantsLegGeometry()`/`buildGloveGeometry()`/`buildSockGeometry()`)」だけを持ち、左右対称ペア化のロジックは持たない(shoes は `geometry/shoes.ts` 自体が無く、プロファイル生成+Lathe化+非一様スケールもすべてノードグラフ側にある、上記参照)。
- `neckline.ts` — `necklineWeight(weights, angle)`。ノードグラフ側で作られた落ち込み量の曲線(正面からの角度を 0〜1 に正規化した値を x、重みを y とする点列。round/v/square の形は `generic/necklineShapes.ts` の `necklineShapes` グループが作る)を、角度の位置で線形補間して返す、`ringGrid.ts` が使うフォールオフ関数。正面から±60° を超えると常に0。
- `ringGrid.ts` — `buildRingGridGeometry()`。角度×高さのリングからなる手組みの `BufferGeometry` を、行ごとの半径/Y座標のリストから組み立て、最上段のリングの頂点のみを角度ごとに(`necklineWeights`(落ち込み量の曲線)を `neckline.ts` のフォールオフ関数で角度ごとに引いて重み付けして)引き下げてネックラインを彫り込む。`nodes/definitions/generic/ringGridGenerator.ts` がノードグラフへ薄く配線し、top/dress が共有する。
- `taperedTube.ts` — `buildTaperedTube()`。始点から終点まで、両端の断面(幅×厚み、楕円または矩形)を直線的に補間する、キャップ無しの2リングのチューブ。軸が Y と平行でなければ断面の幅方向(tangent)は水平、そうでなければ +X(`tubeFrame()`)。`nodes/definitions/generic/taperedTubeGenerator.ts`(断面の形ごとに `taperedEllipseTubeGenerator`/`taperedRectTubeGenerator` の2ノードを登録する)がノードグラフへ薄く配線する(`points` 型を扱う `latheGenerator.ts` と同じ理由で `defineGeneratorNode()` ではなく直接 `registerNodeType()` で定義)。頂点属性は position/normal のみ(uv 無し、`mergeGeometry` が uv の有無の違いを吸収する)。
- `alignedBox.ts` — `buildAlignedBox()`。2点間を結ぶよう回転+平行移動した `THREE.BoxGeometry` を作る。回転+平行移動のみの剛体変換なので、標準プリミティブが元々持つ正しい巻き順がそのまま保たれる。`nodes/definitions/generic/alignedBoxGenerator.ts` がノードグラフへ薄く配線する(始点・終点をそれぞれ X/Y/Z の3ソケットに分解しているのは、座標を求める四則演算チェーンを可視の配線として展開できるようにするため。`points` 型を扱う `latheGenerator.ts` と同じ理由で `defineGeneratorNode()` ではなく直接 `registerNodeType()` で定義している)。bag のストラップ・glasses のブリッジ/テンプルが使う。
- `primitives.ts` — `buildCapsuleGeometry()`/`buildSphereGeometry()`/`buildCylinderGeometry()`/`buildTorusGeometry()`/`buildBoxGeometry()` という、THREE.js 標準プリミティブ(CapsuleGeometry/SphereGeometry/CylinderGeometry/TorusGeometry/BoxGeometry)をそのまま返すだけの、特定のガーメント/パーツに紐付かない汎用ジオメトリ関数群。`nodes/definitions/generic/capsuleGenerator.ts`/`sphereGenerator.ts`/`cylinderGenerator.ts`/`torusGenerator.ts`/`boxGenerator.ts` がノードグラフへ薄く配線する。`bodyGroupNode.ts` が Capsule/Sphere を胴体/頭に、Cylinder(`limbPair.ts` 経由)を腕/脚として使い、`mergeGeometry` で1つに結合してから単一の `sceneOutput` へ渡す(`nodes/CLAUDE.md` の「グループノード」節参照)。腕/脚1組は `cylinderGenerator` の出力を汎用グループノード `mirrorPair`(上記参照)へ渡して左右対称ペアにまとめる。bag/glasses は、単純な `.translate(x,y,z)` だけで配置できるパーツ(bag のバッグ本体、glasses の左右レンズ)と `alignedBoxGenerator`(2点間に整列させる回転+平行移動)を使うパーツ(bag のストラップ、glasses のブリッジ/テンプル)の両方を持つガーメントで、前者は `boxGenerator`/`torusGenerator`(プリミティブ生成)→`translate`(いずれも `translate`、bag は X/Y/Z、glasses は Z だけを配線)、後者は `alignedBoxGenerator` というノードグラフへそれぞれ切り出し、`mergeGeometry` で結合している(どちらも専用の `build*Geometry()` は持たない)。

放射対称な Lathe では表現できない形状は、それぞれ別の技術で構築しています:

- top/dress は専用の `build*Geometry()` を持たない。Lathe/Extrude では**ない**(ネックラインの落ち込みは放射対称ではないため)。どちらも `easedLatheProfile`(半径プロファイル)→`ringGridGenerator`(`ringGrid.ts` の `buildRingGridGeometry()` を呼ぶ、`latheGenerator` の放射非対称版)という同じ2ノードで組む。top は始点・終点とも torsoRadius の一定半径のプロファイル、dress は肩(torsoRadius)から裾(hemRadius)へイージングするプロファイルで、`latheGenerator` と同じ下→上の順の points を `ringGridGenerator` が上→下へ並べ直して渡す。
- 袖は専用の `build*Geometry()` を持たず、汎用グループ `sleevePair`(`nodes/definitions/generic/sleevePair.ts`)が原点から水平より36°下へ `sleeveLength` だけ伸びる `taperedEllipseTubeGenerator` 1本(円形断面、終端の直径は始端の0.85倍)を作り、`mirrorPair` で胴体の壁より内側の `±attachRadius × 0.75` へ複製して左右の袖にする(左袖は `mirrorPair` 内の鏡像反転)。トルソーの壁面に食い込ませて重ねたままにしている(`bodyLayoutGroupNode.ts` の `armTorsoOverlapRatioIn` が腕に対して使っているのと同じ、意図的な交差を許容するアプローチで、ブーリアン演算や穴あけは行わない)。`topGroup` の内部で `ringGridGenerator` と並べて使われ、Top と同じ(Body Build 適用後の)胴体半径を付け根半径として受け取り、結合後の1つのジオメトリとして同じ `toonMaterial`・同じ `shoulder` アンカーで描画される。これにより top の色を変えると袖も一緒に再着色される(`nodes/definitions/groups/topGroupNode.ts` 参照)。
- necktie は専用の `build*Geometry()` を持たない。結び目(`boxGenerator`→`translate`)とブレード(`taperedRectTubeGenerator`、上端 `bladeTopWidth`→下端 `bladeBottomWidth` のテーパー)を `mergeGeometry` で結合している。
- マネキンの寸法計算(`heightScale`/`buildScale`/`shoulderScale` から各部位の半径・長さ・Y座標、および `waist`/`shoulder`/`feet`/`wrist`/`head` アンカー座標を求める式)は、`geometry/` 配下の純粋関数としては存在しません。式の実体は `bodyDimensionsGroupNode.ts`/`bodyLayoutGroupNode.ts` というノードグラフのテンプレート定義そのものが唯一の真実の源です(コード側に並行する純粋関数は無い、ノードエディタ上で式がそのまま見える形にするため)。`bodyDimensionsGroup`/`bodyLayoutGroup` 自体は `bodyGroupNode.ts`/`garmentPlacement.ts` のどちらにもネストされておらず、`src/state/initialGraph.ts` 側のトップレベル共有ノード(id: `bodyDimensions`/`bodyLayout`)としてただ1組だけ存在し、`bodyGroup` と全14ガーメントへ計算済みの値をファンアウトする(`nodes/CLAUDE.md` の「グループノード」節参照)。ボディのリサイズに合わせてアンカーが一緒に動きます。

- bag のストラップは `bagGroupNode.ts` 側で `alignedBoxGenerator`(始点 `(shoulderOffset, 0, strapStartDepthIn)` → 終点 `(negatedHipOffset, negatedDrop, bagFrontDepthCalc)`)として組み立てる。バッグ本体は `boxGenerator`(width/height/depth)→`bodyTranslate`(`translate` グループ、`x = negatedHipOffset = 0 - hipOffset × bodyBuild`、`y = bagCenterY = (0 - drop) - bagHeight × 0.5`、`z = bagFrontDepthCalc = 0.18 × bodyBuild`)というノードグラフで組み立て(体の側面の位置と前面の深さは胴体の壁と同様に Body Build でスケールする)、最後に `mergeGeometry` でストラップと結合する — ストラップの終点とバッグ本体は `negatedHipOffset`/`negatedDrop`/`bagFrontDepthCalc` の計算結果を共有する。
- glasses は `glassesGroupNode.ts` が、レンズ・テンプル・ブリッジの3つのパーツをそれぞれ別のグループノード(`glassesLensPair`/`glassesTemplePair`/`glassesBridge`、`nodes/definitions/generic/`)として組み立て、1つの `mergeGeometry` で結合する。ブリッジ(`alignedBoxGenerator`)は1本の箱で、`bridgeXOffset = lensSpacing - lensRadius` の ± を両端の X に、Y=0・Z=`forwardDepth` は両端で共通。テンプル(`alignedBoxGenerator`)は X=0 に1本だけ作り(前面 `forwardDepth` から後方 `templeBackZ = (forwardDepth - 0.02) - 0.12` まで Z 方向に伸ばす)、`mirrorPair` で `templeXOffset = lensSpacing + lensRadius` の ± へ複製する。レンズも1つだけ `torusGenerator`(radius=lensRadius、tube=frameThicknessの半分)→`translate`(Z だけを配線、`forwardDepth` = 頭半径 − 0.02、既定で 0.14)で作り、`mirrorPair` で `lensSpacing` の ± へ複製する。3パーツが共有する `lensRadius`/`lensSpacing`/`forwardDepth` は `glassesGroup` が持って各パーツへ配線する。
- scarf は `geometry/scarf.ts` 自体が存在しない。首元の輪(帯)は belt と共有する `bulgedBand` を `bulge=1.05` 固定で `scarfGroupNode.ts` にネストして再利用し、タイは `boxGenerator`→`translate`(Y: `(0-bandThickness) - tailLength×0.5`、Z: `neckRadius(スケール後) × 0.9` という可視の四則演算チェーンで導出)へ展開して `mergeGeometry` で結合している。

**すでに一度踏んだ落とし穴(新しいジオメトリを追加すると再びハマります):**

- 三角形の巻き順(winding order)は重要で、逆になりやすいです。しかも視覚的な症状は分かりやすい「裏返って見える」ではなく、ガーメントが**真っ黒なシルエット**としてレンダリングされる(端に本来の色がわずかに見えることもある)というものです。これは、実際の `FrontSide` メッシュが(誤って)カリングされると、アウトラインメッシュの `BackSide` 専用の面だけが唯一の可視面になってしまうために起きます。新しい手続き型メッシュが真っ黒にレンダリングされたら、まずマテリアルやライティングではなく三角形の巻き順を確認してください。`windingTestHelpers.ts` の `expectOutwardWinding()` で自動検証できますが、対象が単純な放射対称形状でない場合は既定の axisPoint(Y軸基準)では誤検知します — 箱(BoxGeometry)には自身の中心点、トーラス(TorusGeometry)には中心線円上の最近点というように、形状に応じた正しい基準点を渡す必要があります(`alignedBox.test.ts` 参照)。
- `mergeGeometries()`(`three/examples/jsm/utils/BufferGeometryUtils.js`)は、結合するすべてのジオメトリが**同じ頂点属性**(名前・itemSize)を持っていることを要求します。標準プリミティブ(position/normal/uv を持つ)と手組みの `BufferGeometry`(position のみ)を混ぜて結合しようとすると、警告を出して `null` を返し、その後の呼び出しが `Cannot read properties of null` で落ちます(`mergeGeometry` ノードは uv の有無だけが違う場合、入力を clone して uv を外してから結合し直すため、`boxGenerator` と `taperedRectTubeGenerator` のような組み合わせを普通に繋げる)。
- アンカーは体の中心線(x=0, z=0)上の1点のみです。体の前面より前に出すべきアクセサリ(ネクタイ、バッグ、メガネなど)は、z=0 付近に置くとガーメントの壁の内側/裏側に埋もれて見えなくなります(`necktieGroupNode.ts` の `frontDepthIn`(Body Build でスケール)、`bagGroupNode.ts` の `bagFrontDepthCalc`(0.18 × Body Build)/`glassesGroupNode.ts` の `forwardDepthCalc`(頭半径 − 定数)を参照)。さらに、デフォルトグラフのように複数のガーメントが同じアンカーを同時に共有していると、後から広がる大きなガーメント(dress/jacket など)が薄いアクセサリ(necktie/bag など)を覆い隠すことがあります — これはバグではなく、複数の出力ノードが同じアンカーを共有する際の一般的な特性です(`src/scene/CLAUDE.md` の「シーン組み立て」参照)。
