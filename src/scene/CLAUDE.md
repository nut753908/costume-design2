# src/scene/ のガイダンス

全体のアーキテクチャ概要は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## シーン組み立て

`Scene.tsx` は `Body`(静的)と `Garments`(動的)をレンダリングします。`Garments.tsx` は `useGraphStore((s) => s.rootEvaluatedResults)`(トップレベル視点で合成した完全なグラフの評価結果、`state/useRootEvaluatedGraph.ts` が書き込む — グループノードの中に入っている間も他のガーメントが消えないよう、`s.nodes`/`s.evaluatedResults` ではなくこちらを見る。詳細は `src/state/CLAUDE.md` の「グループの中に入る」節)を走査しますが、**すべてのエントリではなく `sceneOutput` 型のノード(`nodes/definitions/sceneOutput.ts`)へ実際に配線されているものだけ**を描画対象にします(`useRootGraphLite()` でトップレベル視点のノード一覧を別途引き、`type === 'sceneOutput'` の id 集合でフィルタする)。各ガーメントの `<name>Group` 自身の評価結果にも `geometry`+`material` は既に含まれています(グループ内部の `groupOutput` から転送されるため)が、それだけでは描画対象になりません — `initialGraph.ts` 側で `<name>Group.geometry`/`.material` を対応する `<name>Output`(`sceneOutput`)へ明示的に配線して初めて `ToonMesh` がマウントされます。これは「型が `geometry`+`material` を持っていれば自動描画される」という以前の暗黙の検出から、「`sceneOutput` への配線そのものが描画の仕様になる」という明示的な形に変更したものです。**取り付け位置(anchor/offsetY)はここでは扱いません** — 各ガーメントグループの内部で `garmentPlacement` ノードが、`enumInput`/`numberInput`(`anchorIn`/`offsetYIn`)から受け取った anchor/offsetY と `geometry/body.ts` の純粋関数から計算した実座標を使って geometry の頂点そのものを平行移動済みだからです(Blender の Geometry Nodes で位置をジオメトリに焼き込む考え方と同じ、`src/nodes/CLAUDE.md` の「グループノード」節参照)。そのためここで `Garments.tsx` が必要とするのは `sceneOutput` の評価結果が持つ `geometry`+`material` の2キーだけです。複数のガーメントが同じアンカー由来の座標を共有することもでき(top と sleeve はどちらも `shoulder`)、その場合は単に重なり合う別々のメッシュとしてレンダリングされます。
