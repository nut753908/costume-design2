# src/editor/ のガイダンス

全体のアーキテクチャ概要は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## ノードグラフの操作(エディタUX)

- ノードの追加方法は3通りあります: (1) パレット(`NodePalette.tsx`)の項目をクリックするとカスケード状のオフセットで追加、(2) パレットの項目をキャンバスへドラッグ&ドロップすると、ドロップした座標に追加、(3) キャンバスを右クリックするとその場に `ContextMenu.tsx` が開き、選んだノードタイプがクリック位置に追加されます。いずれも最終的には `useGraphStore().addNode(type, position)` を呼び出しており、位置の変換には React Flow の `screenToFlowPosition` を使っています(そのため `NodeEditor.tsx` は `ReactFlowProvider` で自身をラップし、内側のコンポーネントで `useReactFlow()` を呼ぶ構成になっています)。カテゴリ別のノードタイプ一覧は `nodes/registry.ts` の `groupNodeTypesByCategory()` に共通化されており、パレットとコンテキストメニューの両方がこれを参照します。`NodePalette.tsx` 上部の検索ボックスでラベルの部分一致による絞り込みもできます。
- ノード/エッジの削除は、選択して Backspace を押します(React Flow のデフォルト、ノード・エッジ上に削除ボタンは無い)。ノードを右クリックすると `NodeContextMenu.tsx` が開き、選択中のノード(複数選択中ならその選択全体、右クリックしたノードが未選択ならそのノード単体)に対して複製/コピー/削除を実行できます。
- キーボードショートカット: `Ctrl+D` で選択ノードを複製、`Ctrl+C`/`Ctrl+V` でコピー&ペースト(選択範囲の内部エッジのみ複製し、外部への接続は複製しない。連続ペーストはオフセットがカスケードする)、`Ctrl+Z`/`Ctrl+Shift+Z`(または `Ctrl+Y`)で Undo/Redo。テキスト入力中はこれらのショートカットをブラウザ/入力欄のネイティブな挙動に譲ります(`editor/keyboardGuards.ts` の `isEditableTextTarget`、`HistoryControls.tsx` と `NodeClipboard.tsx` で共有)。
- `GraphIO.tsx` の「Arrange」ボタンは `nodes/autoLayout.ts` の `computeAutoLayout()` を呼び、入力→中間→出力へのトポロジカルな層(最長経路)に沿ってノードを自動整列します。このアプリのグラフは入力ノードが1つの層に大量に集まる星型に近い形になりやすいため、1層あたり最大14行を超えたら次のサブ列に折り返し、極端に縦長にならないようにしています。React Flow 標準の `MiniMap` でキャンバス全体を俯瞰できます(右下、ペインが狭いため小さめのサイズに調整)。
- **グループノード(`category:'group'`)はダブルクリックで中に入れます**。`GenericNode.tsx` がダブルクリックを検知して `useGraphStore().enterGroup(id)` を呼び、キャンバスがそのノードインスタンスの内部だけの表示に切り替わります(React Flow 標準の `parentId`/`extent` によるインライン常時表示ではなく、Blender/Houdini のようにキャンバス全体を差し替える方式 — 詳細は `src/nodes/CLAUDE.md`・`src/state/CLAUDE.md`)。`BreadcrumbPanel.tsx` が中に入っている間だけ現在の階層パスを表示し(`Panel position="top-center"`、`HistoryControls.tsx` と同じ位置に自動で縦に積まれる)、クリックで任意の階層またはトップレベルへジャンプできます(先頭の「トップレベル」ボタンは `.breadcrumb-panel__crumb` に含まれない直接の子要素なので注意)。中に入る/出るたびに `fitView()` を呼び直し、新しいスコープのノード群が画面内に収まるようにしています(`fitView` prop は初回マウント時にしか効かないため)。`fitView()`/`fitViewOptions`(`NodeEditor.tsx`)・`Arrange` 後の `fitView()`(`GraphIO.tsx`)はいずれも `paletteShared.ts` の `fitViewPadding()` を渡している — 単純な均等割合パディングだと、`NodePalette`(画面座標に固定表示、幅は内容依存だが実測200px前後)が、`computeAutoLayout()` が常に列0(キャンバス左端)に置く入次数0のノード(`groupInput` など)を覆い隠してしまうことがあり(実際に発生した不具合: グループの中に入るたびに Group Input のカードがパレットの下に完全に隠れ、外から見ると出力に配線が無いように見えた)、左側だけ固定 px(他3辺は従来どおり割合)にすることでこれを避けている。

`<ReactFlow>` 要素には `key={scopeDepth}` を付けている。これが無いと、多段ネスト(`bodyGroup` の中に `bodyDimensionsGroup` がネストするなど)でグループへの出入りを繰り返した際、両方の内部グラフで慣例的に同じ id(`groupInput`/`groupOutput` は id `'input'`/`'output'`、`nodes/CLAUDE.md` 参照)が使われているせいで、`<ReactFlow>` 自身はアンマウントされず `nodes`/`edges` props だけが丸ごと差し替わる(下記参照)構造上、React が id の再利用を「同一要素の更新」と誤認し、React Flow 内部の Handle 位置計測キャッシュが古いままになって、そのノードから伸びるエッジが実際には(ストアのデータ上は)正しく繋がっているのに描画されなくなる、という不具合が実際に発生した(グラフのデータ自体は Export JSON で確認しても正しいままだったため、純粋に描画側のバグだった)。`key={scopeDepth}` によりスコープが変わるたびに `<ReactFlow>` を強制的にアンマウント→再マウントさせ、内部キャッシュを毎回まっさらな状態から作り直すことでこれを避けている(副作用として `NodePalette` の検索文字列などスコープを跨いで保持する意味の無い軽量な子コンポーネントのローカル state もリセットされるが、実害はない)。
- **グループの外部入出力インターフェースは、中に入って「Group Input」「Group Output」ノード(`category:'group-io'`)にソケットを増減・配線して定義します**(Blender の Geometry Nodes と同じ方式、詳細は `src/nodes/CLAUDE.md` の「グループノード」節)。`NodePalette.tsx`/`ContextMenu.tsx` はどちらも `useGraphStore().scopeStack.length > 0`(グループの中に入っている)場合だけ「Group I/O」カテゴリを一覧に含める — トップレベルでは隠す。
- **ノードカードの未接続の `number`/`color` 入力ソケット(`SocketDef.default` があるもの)の行には、`SocketField.tsx` の入力欄が出る**(配線済みのソケットには出ない)。数値欄/カラーピッカーは `numberInput`/`colorInput` と同じく、入力途中の値をローカル state で持ち、store への反映は `useThrottledNodeDataUpdate` で間引く。欄は行のコンテンツ高さ(16.8px)に収まる高さ(16px)にしてあり、欄の有無でカード高さ(`nodes/autoLayout.ts` の `CARD_ROW_HEIGHT`)は変わらない。 `Group Input` ノードのソケット行(`GroupInputNode.tsx`)も同じ `SocketField` で、親スコープ側で配線されていない `number`/`color` ソケットのデフォルト値(`socket.default`)をその場で編集できる(グループカードの未接続入力の欄の初期値になる)。
- **numberInput は数値入力欄(`type="number"`)で値を直接入力し、colorInput は色をノードカード上で直接編集できます**(ノードのラベルは編集できない)。numberInput は `data.value` だけを持ち、入力値に範囲の制限は無い(入力欄の `step` は矢印キーの刻み 0.01 だけに使う)。colorInput の色はネイティブ `<input type="color">` だけで選ぶ(カラーコードのテキスト欄は無い)。これら専用UI系ノードのカード高さは `nodes/autoLayout.ts` の `BESPOKE_NODE_HEIGHTS` で実測較正されているため、これらのノードの見た目(行の増減)を変えたらこの定数を再計測して更新すること — 怠るとグループの中に入った際に自動レイアウトされたノード同士が重なる(実際にこの機能追加時に発生した)。
- ノードカードのタイトルは常に固定(`NodeTitleBar` に型ごとの `def.label`、入力ノードは Number/Color を渡す)で、ノードインスタンスに表示名(ラベル)は持たせない。ノードの識別の手がかりはノード id。
