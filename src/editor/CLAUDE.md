# src/editor/ のガイダンス

全体のアーキテクチャ概要は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## ノードグラフの操作(エディタUX)

- ノードの追加方法は3通りあります: (1) パレット(`NodePalette.tsx`)の項目をクリックするとカスケード状のオフセットで追加、(2) パレットの項目をキャンバスへドラッグ&ドロップすると、ドロップした座標に追加、(3) キャンバスを右クリックするとその場に `ContextMenu.tsx` が開き、選んだノードタイプがクリック位置に追加されます。いずれも最終的には `useGraphStore().addNode(type, position)` を呼び出しており、位置の変換には React Flow の `screenToFlowPosition` を使っています(そのため `NodeEditor.tsx` は `ReactFlowProvider` で自身をラップし、内側のコンポーネントで `useReactFlow()` を呼ぶ構成になっています)。カテゴリ別のノードタイプ一覧は `nodes/registry.ts` の `groupNodeTypesByCategory()` に共通化されており、パレットとコンテキストメニューの両方がこれを参照します。`NodePalette.tsx` 上部の検索ボックスでラベルの部分一致による絞り込みもできます。
- ノード削除は各ノードカードのタイトル行にある×ボタン(`NodeTitleBar`)、エッジ削除はエッジ中央に表示される×ボタン(`DeletableEdge`)から行えます。選択後の Backspace による削除(React Flow のデフォルト)も引き続き使えます。ノードを右クリックすると `NodeContextMenu.tsx` が開き、選択中のノード(複数選択中ならその選択全体、右クリックしたノードが未選択ならそのノード単体)に対して複製/コピー/削除を実行できます。
- キーボードショートカット: `Ctrl+D` で選択ノードを複製、`Ctrl+C`/`Ctrl+V` でコピー&ペースト(選択範囲の内部エッジのみ複製し、外部への接続は複製しない。連続ペーストはオフセットがカスケードする)、`Ctrl+Z`/`Ctrl+Shift+Z`(または `Ctrl+Y`)で Undo/Redo。テキスト入力中はこれらのショートカットをブラウザ/入力欄のネイティブな挙動に譲ります(`editor/keyboardGuards.ts` の `isEditableTextTarget`、`HistoryControls.tsx` と `NodeClipboard.tsx` で共有)。
- `GraphIO.tsx` の「Arrange」ボタンは `nodes/autoLayout.ts` の `computeAutoLayout()` を呼び、入力→中間→出力へのトポロジカルな層(最長経路)に沿ってノードを自動整列します。このアプリのグラフは入力ノードが1つの層に大量に集まる星型に近い形になりやすいため、1層あたり最大14行を超えたら次のサブ列に折り返し、極端に縦長にならないようにしています。React Flow 標準の `MiniMap` でキャンバス全体を俯瞰できます(右下、ペインが狭いため小さめのサイズに調整)。
- **グループノード(`category:'group'`)はダブルクリックで中に入れます**。`GenericNode.tsx` がダブルクリックを検知して `useGraphStore().enterGroup(id)` を呼び、キャンバスがそのノードインスタンスの内部だけの表示に切り替わります(React Flow 標準の `parentId`/`extent` によるインライン常時表示ではなく、Blender/Houdini のようにキャンバス全体を差し替える方式 — 詳細は `src/nodes/CLAUDE.md`・`src/state/CLAUDE.md`)。`BreadcrumbPanel.tsx` が中に入っている間だけ現在の階層パスを表示し(`Panel position="top-center"`、`HistoryControls.tsx` と同じ位置に自動で縦に積まれる)、クリックで任意の階層またはトップレベルへジャンプできます(先頭の「トップレベル」ボタンは `.breadcrumb-panel__crumb` に含まれない直接の子要素なので注意)。中に入る/出るたびに `fitView()` を呼び直し、新しいスコープのノード群が画面内に収まるようにしています(`fitView` prop は初回マウント時にしか効かないため)。
- **グループの外部入出力インターフェースは、中に入って「Group Input」「Group Output」ノード(`category:'group-io'`)にソケットを増減・配線して定義します**(Blender の Geometry Nodes と同じ方式、詳細は `src/nodes/CLAUDE.md` の「グループノード」節)。`NodePalette.tsx`/`ContextMenu.tsx` はどちらも `useGraphStore().scopeStack.length > 0`(グループの中に入っている)場合だけ「Group I/O」カテゴリを一覧に含める — トップレベルでは隠す。専用パネル(旧 `GroupIOPanel.tsx`)は廃止済み。
- **numberInput/enumInput/colorInput はラベル名・min/max/step・選択肢・カラーコードをノードカード上で直接編集できます**。ラベル編集は `NodeTitleBar` の `onLabelChange` prop(渡すとタイトルが `<span>` ではなく編集可能な `<input>` になる、`nodrag` 付き)経由で共通化している。enumInput の選択肢の追加/削除/リネームは、`GroupInputNode.tsx`/`GroupOutputNode.tsx` がソケット一覧編集に使っている `rf-node__io-row`/`rf-node__io-label`/`rf-node__io-remove`/`rf-node__io-add` の CSS クラスをそのまま流用している(概念上は「削除可能な編集行のリスト」という同じ UI パターンのため)。colorInput のカラーコードのテキスト直接入力は、ネイティブ `<input type="color">` の隣に `<input type="text">` を追加し、完全な hex(3桁/6桁)になるまでは store へ反映しない形にしている(入力途中の不完全な文字列で `THREE.Color` を汚さないため)。これら専用UI系ノードのカード高さは `nodes/autoLayout.ts` の `BESPOKE_NODE_HEIGHTS`/`ENUM_INPUT_BASE_HEIGHT` で実測較正されているため、これらのノードの見た目(行の増減)を変えたら両方の定数を再計測して更新すること — 怠るとグループの中に入った際に自動レイアウトされたノード同士が重なる(実際にこの機能追加時に発生した)。
