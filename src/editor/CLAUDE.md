# src/editor/ のガイダンス

全体のアーキテクチャ概要は[ルートの CLAUDE.md](../../CLAUDE.md)を参照してください。

## ノードグラフの操作(エディタUX)

- ノードの追加方法は2通りあります: (1) パレット(`NodePalette.tsx`)の項目をクリックすると、パネル類に重ならないよう、左のパレット列の右端からペインの右端までの中央付近にカスケード状のオフセットで追加、(2) パレットの項目をキャンバスへドラッグ&ドロップすると、ドロップした座標に追加。いずれも最終的には `useGraphStore().addNode(type, position)` を呼び出しており、位置の変換には React Flow の `screenToFlowPosition` を使っています(そのため `NodeEditor.tsx` は `ReactFlowProvider` で自身をラップし、内側のコンポーネントで `useReactFlow()` を呼ぶ構成になっています)。見出し別のノードタイプ一覧は `nodes/registry.ts` の `groupNodeTypesBySection()` に共通化されており、パレットがこれを参照します(見出しは `NodeCategory` から決まり、機能に使われる `group` だけは表示専用の `paletteSection` で「Garments & Body」「Group Parts」「Group」に振り分けます)。`NodePalette.tsx` 上部の検索ボックスでラベルの部分一致による絞り込みもできます。パレットの見出しはクリックで開閉でき(件数付き)、検索中は一致した項目を見つけやすいよう折りたたみに関わらず全て開きます。折りたたみ状態は閲覧者ごとの表示設定として localStorage(`paletteShared.ts`)に保存し、保存が無いときは `geometry-op`/`points`/`group-part` だけを折りたたんでおきます。
- ノード/エッジの削除は、選択して Backspace または Delete を押します(React Flow の `deleteKeyCode` に両方を指定、ノード・エッジ上に削除ボタンは無い。入力欄にフォーカスがあるときは React Flow がキーを無視するため、数値欄の編集中の Delete で削除されることは無い)。ノード・エッジ・範囲選択の枠(React Flow の `onSelectionContextMenu`)を右クリックすると `SelectionContextMenu.tsx` が開き、選択中のノードとエッジ(右クリックした要素が選択済みならその選択全体、未選択ならそれ単体を選択し直す)に対して複製/コピー/削除を実行できます(複製/コピーはノード単位で、ノードが選択に無ければ無効。エッジの右クリックでは削除だけを出す)。背景を右クリックすると `PaneContextMenu.tsx` が開き(ノード追加の一覧は持たない)、「貼り付け」でコピーしたノード群の左上をクリック位置に合わせて貼り付けます(`pasteClipboard(at)`)。`PaneContextMenu.tsx`/`SelectionContextMenu.tsx` はどちらもクリック座標に `position:fixed` で開くため、`NodeEditor.tsx` のノードエディタ枠(`wrapperRef`)の端に近い位置で開くとはみ出しうる — `useClampMenuPosition.ts` が開いた直後に実際の描画サイズを測り、その枠の矩形内に収まるよう `left`/`top` を補正する(補正のタイミングに関する非自明な事情はファイル自身のコメント参照)。
- **接続済みの入力ソケットを左ドラッグすると、そのエッジを外して掴む**(Blender と同じ。別の入力へ落とすと繋ぎ替え、何もない所で離すと外れたまま、掴んで落とすまでで Undo 1回)。入力ソケットはすべて `nodeComponents/InputHandle.tsx` で描く。React Flow にはソケットから既存のエッジを掴む機能が無いため、接続済みのときは `isConnectableStart={false}` で React Flow 自身の接続開始を止め、React Flow がエッジの端を掴むとき(内部の `EdgeUpdateAnchors`)と同じく `@xyflow/system` の `XYHandle.onPointerDown` を接続元の出力ソケットを起点に直接呼ぶ(`@xyflow/system` は `@xyflow/react` が依存するのと同じバージョンに固定して直接依存に入れている — ずれると2重に読み込まれる)。`isConnectableStart={false}` のハンドルは React Flow の CSS で `pointer-events: none` になるため、`.rf-socket--pickup` で戻している。
- **複数接続できる入力ソケット(`SocketDef.multiple`、現在は `mergeGeometry` の `geometries`)は Blender の Join Geometry と同じ縦長のカプセル形で描き、繋いだエッジは結合順(`evaluateGraph()` と同じエッジ配列の順)に上から1本ずつずらして刺す**。寸法は `nodes/multiInputSocket.ts` にまとめ、カード側(`InputHandle.tsx` のカプセルの高さ、`GenericNode.tsx` の行の高さ)と Arrange の高さの見積もり(`nodes/autoLayout.ts` の `estimateNodeHeight()` の `multiInputCounts`)で共有する — カプセルは2本分を最小に接続本数に応じて伸び、行も同じだけ高くなる。刺さる位置は `SocketEdge.tsx` がずらす(React Flow は既定では全エッジをハンドルの中心に刺すため)。エッジは type を指定せずに作るので、`NodeEditor.tsx` の `edgeTypes` で `default` ごと `SocketEdge` に差し替えている(1本しか入らないソケットではずれは常に 0 で、既定のベジェ曲線と同じ)。このソケットを掴むと、押した位置に一番近いエッジを掴む。このソケットへ接続を離すと(新規の接続でも、掴んだエッジを落とす場合でも)、離した位置より上に刺さっているエッジの次に入る(`multiSocketDropSlot.ts` が React Flow の `connection.pointer` とハンドルの DOM 矩形から並び順を求め、`onConnect`/`dropPickedEdge` の `slot` に渡す)。掴んで同じソケットの別の位置へ落とせば結合順を並べ替えられる。
- キーボードショートカット: `Ctrl+D` で選択ノードを複製、`Ctrl+C`/`Ctrl+V` でコピー&ペースト(選択範囲の内部エッジのみ複製し、外部への接続は複製しない。連続ペーストはオフセットがカスケードする)、`Ctrl+Z`/`Ctrl+Shift+Z`(または `Ctrl+Y`)で Undo/Redo。テキスト入力中はこれらのショートカットをブラウザ/入力欄のネイティブな挙動に譲ります(`editor/keyboardGuards.ts` の `isEditableTextTarget`、`HistoryControls.tsx` と `NodeClipboard.tsx` で共有)。
- `GraphIO.tsx` の「Arrange」ボタンは `nodes/autoLayout.ts` の `computeAutoLayout()` を呼び、入力→中間→出力へのトポロジカルな層(最長経路)に沿ってノードを自動整列します。このアプリのグラフは入力ノードが1つの層に大量に集まる星型に近い形になりやすいため、1層あたり最大14行を超えたら次のサブ列に折り返し、極端に縦長にならないようにしています。React Flow 標準の `MiniMap` でキャンバス全体を俯瞰できます(右下、ペインが狭いため小さめのサイズに調整)。
- **グループノード(`category:'group'`)はタイトル行右上の「→」ボタン(`aria-label="グループの中に入る"`)で中に入れます**。`GenericNode.tsx` のこのボタンが `useGraphStore().enterGroup(id)` を呼び、キャンバスがそのノードインスタンスの内部だけの表示に切り替わります(React Flow 標準の `parentId`/`extent` によるインライン常時表示ではなく、Blender/Houdini のようにキャンバス全体を差し替える方式 — 詳細は `src/nodes/CLAUDE.md`・`src/state/CLAUDE.md`)。`BreadcrumbPanel.tsx` が現在の階層パスを左上に表示します(左端固定にしているのは、階層の増減で既存の項目の位置がずれず、同じ場所を続けてクリックして上がれるようにするため。トップレベルでも無効状態の「トップレベル」だけを常に表示し、真下のパレットが出入りのたびに上下しないようにしている)。`@xyflow/react` の `Panel` は同じ `position` の複数インスタンスを自動整列する仕組みを持たず、それぞれが独立して同じ座標に `position: absolute` されるだけなので素朴に並べると重なる — `BreadcrumbPanel`/`NodePalette`/`HistoryControls`/`GraphIO` はいずれも自身では `Panel` を持たず、`NodeEditor.tsx` 側の共有ラッパー `<Panel className="panel-stack ...">`(左上: パンくず→パレット、右上: Export/Import/Arrange→Undo/Redo)に内包され、CSS の `display:flex; flex-direction:column` で縦に積まれる。クリックで任意の階層またはトップレベルへジャンプできます(先頭の「トップレベル」ボタンは `.breadcrumb-panel__crumb` に含まれない直接の子要素なので注意)。表示する階層が変わるたびに `fitView()` を呼び直し、新しいスコープのノード群が画面内に収まるようにしています(`fitView` prop は初回マウント時にしか効かないため)。`fitView()`/`fitViewOptions`(`NodeEditor.tsx`、`<ReactFlow>` 自身の初回マウント用と、`<Controls/>` の「Fit View」ボタン用の2箇所)・`Arrange` 後の `fitView()`(`GraphIO.tsx`)はいずれも `paletteShared.ts` の `fitViewPadding()` を渡している — 単純な均等割合パディングだと、`NodePalette`(画面座標に固定表示、幅は内容依存だが実測200px前後)が、`computeAutoLayout()` が常に列0(キャンバス左端)に置く入次数0のノード(`groupInput` など)を覆い隠してしまうことがあり(実際に発生した不具合: グループの中に入るたびに Group Input のカードがパレットの下に完全に隠れ、外から見ると出力に配線が無いように見えた)、左側だけ固定 px(他3辺は従来どおり割合)にすることでこれを避けている。

`<ReactFlow>` 要素には `key={scopePath}`(`scopeStack` の `parentId` を連結した階層の経路)を付けている。これが無いと、多段ネスト(`bodyGroup` の中に `limbPair` がネストするなど)でグループへの出入りを繰り返した際、両方の内部グラフで慣例的に同じ id(`groupInput`/`groupOutput` は id `'input'`/`'output'`、`nodes/CLAUDE.md` 参照)が使われているせいで、`<ReactFlow>` 自身はアンマウントされず `nodes`/`edges` props だけが丸ごと差し替わる(下記参照)構造上、React が id の再利用を「同一要素の更新」と誤認し、React Flow 内部の Handle 位置計測キャッシュが古いままになって、そのノードから伸びるエッジが実際には(ストアのデータ上は)正しく繋がっているのに描画されなくなる、という不具合が実際に発生した(グラフのデータ自体は Export JSON で確認しても正しいままだったため、純粋に描画側のバグだった)。`key={scopePath}` によりスコープが変わるたびに `<ReactFlow>` を強制的にアンマウント→再マウントさせ、内部キャッシュを毎回まっさらな状態から作り直すことでこれを避けている(副作用として `NodePalette` の検索文字列などスコープを跨いで保持する意味の無い軽量な子コンポーネントのローカル state もリセットされるが、実害はない)。深さではなく経路にしているのは、階層を跨ぐ Undo/Redo(`src/state/CLAUDE.md` の Undo/Redo 節)では同じ深さのまま別のグループの中へ移りうるため。
- **グループの外部入出力インターフェースは、中に入って「Group Input」「Group Output」ノード(`category:'group-io'`)にソケットを増減・配線して定義します**(Blender の Geometry Nodes と同じ方式、詳細は `src/nodes/CLAUDE.md` の「グループノード」節)。パレットの「Group」見出しには自作グループ(`customGroup`)と Group Input/Output が入り、`NodePalette.tsx` は `useGraphStore().scopeStack.length > 0`(グループの中に入っている)場合だけ Group Input/Output を一覧に含める — トップレベルでは隠す。
- **ノードカードの未接続の `number`/`color` 入力ソケット(`SocketDef.default` があるもの)の行には、`SocketField.tsx` の入力欄が出る**(配線済みのソケットには出ない)。数値欄/カラーピッカーは `numberInput`/`colorInput` と同じく、入力途中の値をローカル state で持ち、store への反映は `useThrottledNodeDataUpdate` で間引く。欄は行のコンテンツ高さ(16.8px)に収まる高さ(16px)にしてあり、欄の有無でカード高さ(`nodes/autoLayout.ts` の `CARD_ROW_HEIGHT`)は変わらない。 `Group Output` ノードのソケット行(`GroupOutputNode.tsx`)は、`number`/`color` の入力に何も配線されていなければ同じ `SocketField` でデフォルト値(`socket.default`、未配線ならそのまま出力される)を編集できる。`Group Input` ノードのソケット行(`GroupInputNode.tsx`)にはデフォルト値の欄も配線された値の表示も無く、値の変更はグループカードの未接続入力の欄(`number`/`color`)で行う。
- **numberInput は数値入力欄(`type="number"`)で値を直接入力し、colorInput は色をノードカード上で直接編集できます**(ノードのラベルは編集できない)。numberInput は `data.value` だけを持ち、入力値に範囲の制限は無い(入力欄の `step` は矢印キーの刻み 0.01 だけに使う)。colorInput の色はネイティブ `<input type="color">` だけで選ぶ(カラーコードのテキスト欄は無い)。カードの高さは Arrange の配置に使うため `nodes/autoLayout.ts` の `estimateNodeHeight()` が見積もっており(専用UI系は `BESPOKE_NODE_HEIGHTS` など、それ以外は行数から)、怠るとノード同士が重なる。**カードの見た目(`nodeEditor.css` や `editor/nodeComponents/*.tsx`)を変えたら `node .claude/skills/run-costume-design2/check-card-heights.mjs` を実行し、全ノードタイプで実機の高さと見積もりが一致するか確認すること**(ずれたら `autoLayout.ts` の定数を直す。レジストリの全タイプが自動で対象になる)。専用のカード UI を持つノードを増やすときは `nodes/customCardTypes.ts` の `CUSTOM_CARD_TYPES` に追加し、高さの見積もりも対応させる(`autoLayout.test.ts` が一致を確認する)。
- **`numberDisplay`/`colorDisplay` は、入力された number の値/color の色をカード上に表示するだけのノード**(専用のカード UI、`Output` カテゴリ)。出力ソケットは宣言せず、カードは自身の評価結果(`evaluatedResults`)の `value`/`color` を読んで表示する(number は小数第4位まで、color はスウォッチと `#hex`、未接続なら「—」)。
- ノードカードのタイトルは原則として型ごとの固定ラベル(`NodeTitleBar` に `def.label`、入力ノードは Number Input/Color Input を渡す)。例外は `renamable` な型(現在は空から組む自作グループ `customGroup` だけ)で、タイトルをダブルクリックすると名前を編集でき(Enter/フォーカス外しで確定、Esc で取り消し、空にすると型のラベルに戻る)、`data.label` に保存される。表示名は `nodes/registry.ts` の `nodeDisplayLabel()` で決め、カード・パンくず・3Dビューのメッシュ一覧で共有する。
- **React Flow 既定の選択状態スタイル(box-shadow)は組み込みの4種類のノードタイプ専用クラス(`react-flow__node-input`/`-default`/`-output`/`-group`)にしか効かない**ため、`nodeTypes` でカスタム型を登録しているこのアプリのノードはどれにも一致せず、素の React Flow ではクリックして選択しても見た目に反映されない。`nodeEditor.css` の `.react-flow__node.selected .rf-node`(全カード共通のルート要素)で明示的に枠線を付けている。Tab/Shift+Tab でノードまたはカード内の欄へフォーカスが移ると、そのノード単体を選択する(`NodeEditor.tsx` の `handleFocus`。マウスのクリックでもフォーカスは移るため、直前のキーが Tab のときに限る)。新しい専用カード UI を追加する場合も、ルート要素に `rf-node` クラスを含めることでこのスタイルの対象に入る。カード上のソケット・入力欄・プルダウン・ボタンの操作ではノードを選択しない(`NodeEditor.tsx` の `nodeTypes` が全カードを `nodeComponents/withControlClickGuard.tsx` で包み、click をカードとノード要素の間で止める)。
