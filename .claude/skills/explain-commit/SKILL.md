# コミットの解説

このリポジトリのコード理解を深めるために、1つのコミットの diff を読み解いて日本語で詳しく解説する手順。

## 手順

0. ユーザーがコミットを指定しなかった場合は `<hash>` として `HEAD` を使う。
1. `git show --stat <hash>` で変更ファイル一覧と規模を把握する。
2. `git show <hash> -- <files...>` で実際の diff を取得する。ファイル数が多い場合は、レイヤー(例: `nodes/`, `state/`, `editor/`, `geometry/`, `rendering/`, `scene/`)ごとにグルーピングして複数回に分けて取得してよい。
3. 意味のある単位(1ファイル、または密接に関連する数ファイルのまとまり)ごとに見出しを立てて解説する。各セクションでは:
   - 追加/変更されたコードの該当部分をスニペットとして引用する。
   - その変更が何を可能にするのか、なぜそう実装されているのかを説明する。
   - 可能であれば `CLAUDE.md` に書かれているアーキテクチャ上の概念(ノードグラフエンジン、evaluator のトポロジカルソート、`state/selectors.ts` の参照安定化、巻き順の落とし穴など)や、これまでのコミットで登場した仕組み(`nodeTypeRegistry`, `NodeTypeDefinition`, `useEvaluatedGraph` など)と結びつけて説明する。単なる「このコードは何をしているか」だけでなく「なぜこの設計なのか」まで踏み込む。
4. 型契約やインターフェースが変更された場合(例: `NodeTypeDefinition` に必須フィールドが増える)、それに追従するために他の全実装ファイルへ機械的な変更が必要になった経緯があれば明示する。
5. 最後に、このコミット全体が何を実現したかを1〜2文でまとめる。

## スタイル

- 応答はすべて日本語(コード識別子は英語のまま)。`CLAUDE.md` の言語ルールに従う。
- 1つのコミットを一度に最後まで解説してよい(ユーザーから明示的に「1ファイルずつ」等の指示がある場合はその粒度に従う)。
- 複数コミットを続けて解説するよう明示的に頼まれない限り、1コミットの解説後は次に進む前にユーザーの反応を待つ。
- 既にこのセッション内で解説済みの概念は、簡潔に「(前述の◯◯と同様)」のように参照し、重複説明を避ける。
